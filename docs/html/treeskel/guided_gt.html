treeskel.guided_gt

Click-guided main-branch ground truth from winter images.

The automatic method (treeskel.winter_gt) is kept as a baseline. It failed on many trees: posts, straight unbranched trees, gaps in depth, support wires, and branches that cross. Here a person supplies a few clicks per tree, and the branches are traced between them automatically:

  1. Clicks (Clicks): the trunk base, the fork, and the tip of each of the two V leaders, plus optional waypoints where a trace needs guiding.

  2. Cost map (branch_cost()): each pixel gets a "woodiness" in [0, 1] from three cues, and a cost floor + (1 - woodiness)^power:

    • depth: the pixel stands out from the ground or background (treeskel.winter_gt.foreground_mask(), smoothed), weighted by how central it is within the object (distance to the edge divided by the largest such distance nearby), so paths run down the middle of thick trunks rather than along an edge;
    • tube shape: the Frangi vesselness filter, which uses the eigenvalues of the image's Hessian (second derivatives) to respond to bright, elongated structures at the chosen widths;
    • colour: bark is pale and unsaturated, unlike grass and soil.

  3. Tracing (trace()): between consecutive clicks, the path with the smallest total cost is found by Dijkstra's algorithm over the 8-connected pixel grid (diagonal steps cost √2 × the pixel cost). Cheap woody pixels pull the path onto the branch, and short gaps are crossed where needed.

  4. Smoothing (smooth_segment()): the pixel path zig-zags by a pixel or two (bark texture, 8-connected steps), so each stretch between clicks is smoothed with the clicks held fixed.
  5. Widths: the trunk's width is measured from depth and fitted as a straight-line taper along its length by robust Huber regression (fit_taper(), huber_line()). Each leader's width is measured across the branch in the colour image (branch_edges()): every cross-section is split into background, branch and background by least squares, so both the sunlit and the shaded half of a branch lit from one side count. Depth is not used for leaders because it reaches about 2 px past each edge and merges with things behind. Each leader is drawn at its own robust width, widened near the fork by an amount shared by all leaders that fades with distance (fit_leader_radius()).
  6. Fork (end_cut(), fork_junction()): drawn as discs, the trunk would end in a half disc of its own radius, which shows as a round knob where the much thinner leaders leave it. So the trunk is cut flat at the fork (and at a root click that is well above the image's bottom edge), and each leader is joined to the trunk's edge on its outer side by a straight line a little way up the leader; the crotch between the leaders is left as the leaders draw it. The older shoulder_fill() (off by default since session 8) closed the notch beside each leader but kept the round top; it was needed while the leaders were drawn about half as wide as their bark.
  7. Result (guided_gt()): a treeskel.winter_gt.WinterGT, so the same rendering, shape measures and overlays apply to both methods.

Clicks are stored in a JSON file keyed by tree id (see save_clicks()), so the ground truth can be regenerated exactly with python -m treeskel.guided_gt DATA_DIR --clicks annotations/winter_clicks.json. Clicks are made with treeskel.annotate.

  96class GuidedParams:
  97    """Settings for the cost map and for drawing the branches.
  98
  99    The cost-map defaults were chosen by :mod:`treeskel.tune_cost` on 17 annotated
 100    trees (64 correction clicks). The first defaults (depth 0.5, tube 0.3,
 101    colour 0.2, power 2, centre weight 0.5) made wood almost free, so paths
 102    wandered within thick trunks and needed many corrections: 62% of the
 103    correction clicks lay more than 8 px from the trace made from the main
 104    clicks alone. The tuned setting keeps wood only moderately cheaper than
 105    background, so path length still matters, and fully favours the centre
 106    of each branch: 6% of correction clicks were more than 8 px off (11% in
 107    leave-one-out cross-validation). The colour cue got weight 0.
 108
 109    Attributes:
 110        depth_weight: Weight of the depth cue in woodiness.
 111        tube_weight: Weight of the Frangi tube cue.
 112        colour_weight: Weight of the pale-bark colour cue.
 113        sigmas: Frangi filter scales (Gaussian sigma, px), roughly half the
 114            branch widths to respond to.
 115        cost_floor: Smallest pixel cost; keeps paths from taking long detours
 116            through very woody areas.
 117        cost_power: Exponent on (1 − woodiness); higher values stick more
 118            tightly to woody pixels.
 119        centre_window: Half-size (px) of the neighbourhood used to judge how
 120            central a pixel is within its object; should exceed the widest
 121            trunk's half-width.
 122        centre_weight: How much the depth cue favours an object's centre line
 123            (0 = not at all, 1 = only the centre line counts fully).
 124        centre_source: ``"depth"`` to judge centredness on the depth
 125            foreground, or ``"wood"`` to judge it on the combined cues.
 126        wood_threshold: Woodiness above which a pixel counts as wood when
 127            ``centre_source="wood"``.
 128        smooth_sigma: Width (px) of the Gaussian that smooths each traced
 129            stretch between clicks (:func:`smooth_segment`); 0 = no smoothing.
 130            Not used by the cost map, so :mod:`treeskel.tune_cost` results
 131            are unaffected.
 132        leader_width_source: How leader widths are measured: ``"profile"``
 133            (default) finds both edges of the branch in colour cross-sections
 134            (:func:`branch_edges`); ``"scale_space"`` uses scale-space ridge
 135            detection (:func:`scale_space_radius`, the default until session
 136            8); ``"depth"`` uses the depth foreground like the trunk. On the
 137            21 development trees in the repository, ``"scale_space"`` gave
 138            about half the width of the bark: it responds to the sunlit half
 139            of a branch lit from one side. Depth reaches a median 2.0 px past
 140            clear bark edges; with that removed, it agrees with
 141            ``"profile"`` (median difference −0.4 px per leader), see
 142            :mod:`treeskel.measure_width`. Trunks always use depth.
 143        leader_scales: Range (px) of Gaussian scales searched for leaders
 144            (``"scale_space"`` only).
 145        scale_window: Half-size (px) of the neighbourhood searched around
 146            each path point, so a slightly off-centre path still finds the
 147            branch (``"scale_space"`` only).
 148        profile_half_width: How far (px) either side of the path each
 149            cross-section reaches (``"profile"`` only); wider than the widest
 150            leader plus a few pixels of background.
 151        profile_along: Cross-sections are averaged over this many path
 152            points either side (``"profile"`` only), which evens out bark
 153            texture and background clutter. Longer averages blurred the edges
 154            where leaders curve.
 155        leader_fit: ``"widening"`` (default) draws each leader at its own
 156            width, widened near the fork (:func:`fit_leader_radius`);
 157            ``"taper"`` fits a free straight taper per leader
 158            (:func:`fit_taper`, the method until session 8). Free tapers are
 159            unreliable: on the 21 development trees here, half of the leaders
 160            came out widening upwards (28% on all 449 development trees).
 161        fork_widening: How much wider a leader is at the fork than its own
 162            width further up (a fraction); 0 turns the widening off.
 163        widening_length: Distance (in trunk radii at the fork) over which
 164            the widening falls by a factor e. ``fork_widening`` and
 165            ``widening_length`` are shared by all leaders, and were chosen on
 166            all 449 development trees (:mod:`treeskel.measure_width`, grid up
 167            to 1.0 and 48 trunk radii): +35% at the fork fading over 12 trunk
 168            radii, so a leader narrows gradually along its length (+31% 1.5
 169            trunk radii from the fork, +15% at 10, +3% at 30). Leave-one-tree-
 170            out picked 0.30–0.35 and 12; the 5 row-grouped folds of
 171            ``splits.json`` picked 0.30–0.35 and 8–12, and on every fold the
 172            shape beat a constant width on held-out rows. (A first fit on 21
 173            trees, 17 of them the problem trees used for tuning, had chosen a
 174            length of 4.)
 175        leader_fit_start: A leader's own width is estimated from points at
 176            least this many trunk radii from the fork; nearer, the
 177            cross-section cuts through the top of the trunk. Cross-sections
 178            that could reach the other leader are not used either
 179            (:func:`clear_of`); on the development trees the first usable
 180            one is a median 2.1 trunk radii from the fork.
 181        shoulder_length: How far up each leader the shoulder fill reaches
 182            (:func:`shoulder_fill`), in multiples of the trunk's radius at
 183            the fork; 0 (the default) turns it off. Session 6 chose 1.4 with
 184            :mod:`treeskel.measure_fork`, when the leaders were drawn about
 185            half as wide as their bark and left a deep notch beside the
 186            trunk. With the leaders at their true width (session 8), the
 187            masks without any fill already cover the shoulder between the
 188            depth silhouette and the silhouette minus its measured 2 px
 189            overshoot, on all 449 development trees (0.914 against
 190            0.875–0.938 at 1.5 trunk radii), while 1.4 covered more than
 191            depth did. So the student turned it off, for the moment; 1.4
 192            restores the session-6 masks' fill (see
 193            ``docs/results/fork_shoulders/``). Not used by the cost map.
 194        junction_reach: How the trunk meets the leaders, in multiples of
 195            the trunk's radius at the fork; 0 keeps the round-ended trunk
 196            of the masks up to session 8. Drawn as discs, the trunk ended in
 197            a half disc of its own radius, and at the fork that round top
 198            showed between and beside the thinner leaders as a knob (the
 199            student's observation in session 8; the hand masks have none).
 200            The trunk is now cut flat at the fork (:func:`end_cut`), and on
 201            each leader's outer side the trunk's edge at the fork is joined
 202            by a straight line to the leader's edge this far up the leader
 203            (:func:`fork_junction`); the crotch between the leaders is left
 204            as the leaders draw it. 1.0 was chosen with
 205            :mod:`treeskel.measure_fork` on the 21 development trees in the
 206            repository, by the criterion that turned the shoulder fill off:
 207            the joins should cover the shoulder beside each leader about as
 208            much as the wood does, which lies between the raw depth
 209            silhouette and the silhouette minus its 2 px overshoot. The
 210            matching reach was 0.98 and 1.30 against the raw silhouette (for
 211            shoulders reaching 1.5 and 2 trunk radii up the leader) and 0.5
 212            or less against the shrunk one; 1.5 covered more than the raw
 213            silhouette at both. On all 449 development trees the matching
 214            reaches were 1.04 and 1.23 (raw) and 0.62 and 0.59 (shrunk), and
 215            1.0 lay between the two references at both
 216            (``docs/results/fork_junction/``). Not used by the cost map.
 217        flat_root: Cut the trunk flat at the root click too
 218            (:func:`end_cut`), where its round end would otherwise be drawn
 219            whole on the ground below the click: on trees whose root click
 220            is more than the trunk's radius above the image's bottom edge
 221            (about 1 in 10 development trees). Most root clicks are a few
 222            pixels above that edge (median 4 px), where the trunk leaves the
 223            frame; there the round end reaches the edge and is kept, since a
 224            flat cut would leave a strip of background under the trunk.
 225    """

 252@dataclass
 253class Clicks:
 254    """Clicked points for one tree, as ``(row, col)`` pixels.
 255
 256    Attributes:
 257        trunk: ``[root, waypoints..., fork]`` (at least two points).
 258        left: ``[waypoints..., tip]`` for the image-left leader; traced from
 259            the fork. If the tips were clicked in the other order,
 260            :meth:`normalised` swaps the leaders.
 261        right: ``[waypoints..., tip]`` for the image-right leader.
 262        skip: True if the tree cannot be annotated (it is then excluded).
 263        note: Free-text reason or comment.
 264    """
 265
 266    trunk: list[Point] = field(default_factory=list)
 267    left: list[Point] = field(default_factory=list)
 268    right: list[Point] = field(default_factory=list)
 269    skip: bool = False
 270    note: str = ""
 271
 272    @property
 273    def complete(self) -> bool:
 274        """True if there is enough to trace: root, fork and both tips."""
 275        return len(self.trunk) >= 2 and bool(self.left) and bool(self.right)
 276
 277    @property
 278    def fork(self) -> Point:
 279        """The fork (last trunk point)."""
 280        return self.trunk[-1]
 281
 282    def normalised(self) -> "Clicks":
 283        """Copy with the leaders swapped if the "left" tip is right of the other.
 284
 285        "Left" always means the leader whose tip is further left in the image,
 286        whatever order the tips were clicked in.
 287        """
 288        if self.left and self.right and self.left[-1][1] > self.right[-1][1]:
 289            return Clicks(trunk=list(self.trunk), left=list(self.right), right=list(self.left),
 290                          skip=self.skip, note=self.note)
 291        return self
 292
 293    def to_json(self) -> dict:
 294        """Plain-data form for the JSON file."""
 295        d = asdict(self)
 296        for k in ("trunk", "left", "right"):
 297            d[k] = [list(map(int, p)) for p in d[k]]
 298        return d
 299
 300    @classmethod
 301    def from_json(cls, d: dict) -> "Clicks":
 302        """Inverse of :meth:`to_json`."""
 303        return cls(
 304            trunk=[tuple(p) for p in d.get("trunk", [])],
 305            left=[tuple(p) for p in d.get("left", [])],
 306            right=[tuple(p) for p in d.get("right", [])],
 307            skip=bool(d.get("skip", False)),
 308            note=str(d.get("note", "")),
 309        )

 320def save_clicks(path: str | Path, clicks: dict[str, Clicks]) -> None:
 321    """Write a clicks file atomically (a crash never leaves it half-written)."""
 322    path = Path(path)
 323    path.parent.mkdir(parents=True, exist_ok=True)
 324    data = {k: clicks[k].to_json() for k in sorted(clicks)}
 325    fd, tmp = tempfile.mkstemp(dir=path.parent, suffix=".tmp")
 326    with os.fdopen(fd, "w") as f:
 327        json.dump(data, f, indent=1)
 328    os.replace(tmp, path)

 331def _centredness(mask: np.ndarray, window: int) -> np.ndarray:
 332    """Distance to the mask edge divided by the largest such distance nearby.
 333
 334    1 on an object's centre line, falling towards 0 at its edges, whatever the
 335    object's width (up to ``window`` px half-width).
 336    """
 337    edt = ndi.distance_transform_edt(mask)
 338    local_max = ndi.maximum_filter(edt, size=2 * window + 1)
 339    return np.divide(edt, local_max, out=np.zeros_like(edt), where=local_max > 0)

 342def cost_cues(rgb: np.ndarray, depth: np.ndarray, valid: np.ndarray,
 343              params: GuidedParams = GuidedParams()) -> dict[str, np.ndarray]:
 344    """The expensive, weight-independent parts of the cost map.
 345
 346    Computed once per image so that many weightings can be tried cheaply
 347    (see :func:`combine_cues` and :mod:`treeskel.tune_cost`).
 348
 349    Args:
 350        rgb, depth, valid: The winter images.
 351        params: Uses ``sigmas`` and ``centre_window``.
 352
 353    Returns:
 354        Dict of ``(H, W)`` float arrays in [0, 1]: ``"fg"`` (smoothed depth
 355        foreground), ``"fg_centred"`` (its centredness), ``"tube"`` (Frangi
 356        response) and ``"pale"`` (bark colour).
 357    """
 358    mask = foreground_mask(depth, valid)
 359    grey = rgb.astype(float).mean(2) / 255.0
 360    tube = frangi(grey, sigmas=params.sigmas, black_ridges=False)
 361    scale = np.percentile(tube, 99.5)
 362    tube = np.clip(tube / scale, 0, 1) if scale > 0 else np.zeros_like(tube)
 363    hsv = rgb2hsv(rgb)
 364    pale = np.clip((hsv[..., 2] - 0.35) / 0.5, 0, 1) * np.clip(1 - hsv[..., 1] / 0.45, 0, 1)
 365    return {
 366        "fg": ndi.gaussian_filter(mask.astype(float), 1.0),
 367        "fg_centred": _centredness(mask, params.centre_window),
 368        "tube": tube,
 369        "pale": pale,
 370    }

 373def combine_cues(cues: dict[str, np.ndarray],
 374                 params: GuidedParams = GuidedParams()) -> tuple[np.ndarray, np.ndarray]:
 375    """Weight the cues into woodiness and cost.
 376
 377    ``woodiness = w_depth · fg · (1 − c + c · centred) + w_tube · tube +
 378    w_colour · pale`` (clipped to [0, 1]), where ``c`` is ``centre_weight``.
 379    ``centred`` is the centredness of the depth foreground
 380    (``centre_source="depth"``) or of the pixels whose woodiness without
 381    centring exceeds ``wood_threshold`` (``centre_source="wood"``). The
 382    latter uses colour and shape too, so ground pixels that merge into the
 383    trunk base in depth do not pull the centre line sideways.
 384
 385    Returns:
 386        ``(cost, woodiness)``; cost is ``cost_floor + (1 − woodiness)^cost_power``.
 387    """
 388    p = params
 389    base = p.tube_weight * cues["tube"] + p.colour_weight * cues["pale"]
 390    if p.centre_source == "wood":
 391        rough = np.clip(p.depth_weight * cues["fg"] + base, 0, 1)
 392        centred = _centredness(rough > p.wood_threshold, p.centre_window)
 393    else:
 394        centred = cues["fg_centred"]
 395    depth_term = cues["fg"] * (1 - p.centre_weight + p.centre_weight * centred)
 396    wood = np.clip(p.depth_weight * depth_term + base, 0, 1)
 397    return p.cost_floor + (1 - wood) ** p.cost_power, wood

 400def branch_cost(rgb: np.ndarray, depth: np.ndarray, valid: np.ndarray,
 401                params: GuidedParams = GuidedParams()) -> tuple[np.ndarray, np.ndarray]:
 402    """Per-pixel woodiness and tracing cost for a winter image.
 403
 404    Args:
 405        rgb: ``(H, W, 3)`` uint8 colour image.
 406        depth: ``(H, W)`` 8-bit depth (brighter = nearer).
 407        valid: ``(H, W)`` bool validity mask.
 408        params: Cue weights and cost shape.
 409
 410    Returns:
 411        ``(cost, woodiness)``, both ``(H, W)`` float arrays; ``woodiness`` is in
 412        [0, 1] and ``cost`` in ``[cost_floor, cost_floor + 1]``.
 413    """
 414    return combine_cues(cost_cues(rgb, depth, valid, params), params)

 417def smooth_segment(seg: np.ndarray, sigma: float) -> np.ndarray:
 418    """Smooth a traced segment while keeping both end points exactly fixed.
 419
 420    The segment is split into the straight line between its end points plus
 421    a residual (the path's sideways wiggle). Only the residual is smoothed,
 422    with a Gaussian of width ``sigma`` (in path steps, about pixels), after
 423    an odd reflection at each end, which keeps the residual zero there. Real
 424    bends are kept, pixel-scale zig-zags are removed, and the result is
 425    re-drawn as a connected 8-connected pixel path.
 426
 427    Args:
 428        seg: ``(M, 2)`` connected path from one click to the next.
 429        sigma: Smoothing width; 0 returns ``seg`` unchanged.
 430
 431    Returns:
 432        ``(K, 2)`` int connected path with the same first and last points.
 433    """
 434    if sigma <= 0 or len(seg) < 5:
 435        return seg
 436    p = seg.astype(float)
 437    step = np.hypot(*np.diff(p, axis=0).T)
 438    t = np.concatenate([[0.0], np.cumsum(step)])
 439    t /= t[-1] if t[-1] > 0 else 1.0
 440    line = p[0] + t[:, None] * (p[-1] - p[0])
 441    res = p - line                                      # zero at both ends
 442    k = min(len(res) - 1, int(4 * sigma) + 1)
 443    ext = np.concatenate([-res[k:0:-1], res, -res[-2:-k - 2:-1]])  # odd reflection
 444    sm = ndi.gaussian_filter1d(ext, sigma, axis=0, mode="nearest")[k:k + len(res)]
 445    sm[0] = sm[-1] = 0.0
 446    pts = np.round(line + sm).astype(int)
 447    out = [tuple(pts[0])]
 448    for a, b in zip(pts[:-1], pts[1:]):
 449        if tuple(b) != out[-1]:
 450            rr, cc = draw_line(out[-1][0], out[-1][1], int(b[0]), int(b[1]))
 451            out.extend(zip(rr[1:].tolist(), cc[1:].tolist()))
 452    return np.array(out, int)

 455def trace(cost: np.ndarray, points: Sequence[Point], smooth_sigma: float = 0.0) -> np.ndarray:
 456    """Cheapest 8-connected path through ``points`` in order.
 457
 458    Args:
 459        cost: ``(H, W)`` positive cost map.
 460        points: Two or more ``(row, col)`` points.
 461        smooth_sigma: If > 0, each stretch between consecutive points is
 462            smoothed by :func:`smooth_segment`; the points themselves stay on
 463            the path.
 464
 465    Returns:
 466        ``(N, 2)`` int array of path pixels from the first to the last point,
 467        passing through every point.
 468    """
 469    h, w = cost.shape
 470    pts = [(min(max(int(r), 0), h - 1), min(max(int(c), 0), w - 1)) for r, c in points]
 471    out: list[tuple[int, int]] = [pts[0]]
 472    for a, b in zip(pts[:-1], pts[1:]):
 473        if a == b:
 474            continue
 475        seg, _ = route_through_array(cost, a, b, fully_connected=True, geometric=True)
 476        seg = smooth_segment(np.array(seg, int), smooth_sigma)
 477        seg[:, 0] = seg[:, 0].clip(0, h - 1)
 478        seg[:, 1] = seg[:, 1].clip(0, w - 1)
 479        out.extend(tuple(q) for q in seg[1:].tolist())
 480    return np.array(out, int).reshape(-1, 2)

 483def guided_gt(rgb: np.ndarray, depth: np.ndarray, valid: np.ndarray, clicks: Clicks,
 484              params: GuidedParams = GuidedParams(), cost: np.ndarray | None = None) -> WinterGT:
 485    """Trace the trunk and both leaders through the clicked points.
 486
 487    Args:
 488        rgb, depth, valid: The tree's winter images.
 489        clicks: Complete :class:`Clicks` (not skipped).
 490        params: Settings; the cost-map ones are ignored if ``cost`` is given.
 491        cost: Precomputed cost map, to avoid recomputing it while clicking.
 492
 493    Returns:
 494        A :class:`treeskel.winter_gt.WinterGT` with ``ok=True``. Its
 495        ``tree_mask`` is the depth foreground, used for branch widths.
 496
 497    Raises:
 498        ValueError: If the clicks are skipped or incomplete.
 499    """
 500    if clicks.skip or not clicks.complete:
 501        raise ValueError("clicks must be complete and not skipped")
 502    clicks = clicks.normalised()
 503    if cost is None:
 504        cost, _ = branch_cost(rgb, depth, valid, params)
 505    fg = ndi.binary_closing(foreground_mask(depth, valid), disk(2))
 506    sm = params.smooth_sigma
 507    trunk = trace(cost, clicks.trunk, sm)
 508    left = trace(cost, [clicks.fork, *clicks.left], sm)
 509    right = trace(cost, [clicks.fork, *clicks.right], sm)
 510    radius = ndi.distance_transform_edt(fg)
 511    skel = np.zeros(fg.shape, bool)
 512    for p in (trunk, left, right):
 513        skel[p[:, 0], p[:, 1]] = True
 514    measured = {k: radius[p[:, 0], p[:, 1]] for k, p in (("trunk", trunk), ("left", left), ("right", right))}
 515    if params.leader_width_source == "profile":
 516        for k, p, other in (("left", left, right), ("right", right, left)):
 517            first, last = branch_edges(rgb, p, params.profile_half_width, params.profile_along)
 518            widths = (last - first + 1) / 2.0
 519            # Near the fork a cross-section can reach the other leader and take it in too.
 520            widths[~clear_of(p, other, params.profile_half_width + NEIGHBOUR_MARGIN)] = np.nan
 521            measured[k] = widths
 522    elif params.leader_width_source == "scale_space":
 523        grey = rgb.astype(float).mean(2) / 255.0
 524        both = np.concatenate([left, right])
 525        r = scale_space_radius(grey, both, params.leader_scales, params.scale_window)
 526        measured["left"], measured["right"] = r[:len(left)], r[len(left):]
 527    elif params.leader_width_source != "depth":
 528        raise ValueError(f"unknown leader_width_source {params.leader_width_source!r}")
 529    radii = {"trunk": fit_taper(trunk, measured["trunk"], "trunk")}
 530    fork_r = _fork_radius(radii)
 531    for k, p in (("left", left), ("right", right)):
 532        if params.leader_fit == "widening":
 533            radii[k] = fit_leader_radius(p, measured[k], fork_r, params.fork_widening, params.widening_length,
 534                                         params.leader_fit_start, part=k)
 535        elif params.leader_fit == "taper":
 536            radii[k] = fit_taper(p, measured[k], k)
 537        else:
 538            raise ValueError(f"unknown leader_fit {params.leader_fit!r}")
 539        # A leader cannot start wider than the trunk it grows from.
 540        radii[k] = np.minimum(radii[k], fork_r)
 541    gt = WinterGT(
 542        tree_mask=fg, skeleton=skel, radii=radii,
 543        root=tuple(map(int, trunk[0])), fork=tuple(map(int, trunk[-1])),
 544        trunk=trunk, left=left, right=right,
 545        trunk_shape=path_shape(trunk, radius), left_shape=path_shape(left, radius),
 546        right_shape=path_shape(right, radius), ok=True,
 547    )
 548    # Fill the notches between the trunk and each leader's outer side (none if shoulder_length is 0).
 549    gt.shoulders = fill_shoulders(gt, params.shoulder_length)
 550    cuts = []
 551    if params.junction_reach > 0:
 552        # Square the trunk's top off, and join it to each leader with straight sides.
 553        cuts.append(end_cut(trunk, radii["trunk"][-1]))
 554        gt.junction = fork_junction(gt, params.junction_reach)
 555    if params.flat_root and trunk[0, 0] + radii["trunk"][0] < fg.shape[0] - 1:
 556        # The round end would lie wholly in the image, on the ground below the click. (Nearer the
 557        # bottom edge, the trunk leaves the frame, and the round end reaches the edge: kept.)
 558        cuts.append(end_cut(trunk[::-1], radii["trunk"][0]))
 559    gt.trunk_cuts = [c for c in cuts if c is not None] or None
 560    return gt

 574def clear_of(path: np.ndarray, other: np.ndarray, distance: float) -> np.ndarray:
 575    """True for the points of ``path`` further than ``distance`` px from every point of ``other``.
 576
 577    Used to drop cross-sections that could include the other leader: near
 578    the fork the two leaders are close together, and a cross-section across
 579    one then takes in the other as well. On a synthetic tree with leaders of
 580    constant width, such cross-sections measured the leaders 1.7–2.4 times too
 581    wide up to 3 trunk radii from the fork.
 582    """
 583    if len(path) == 0 or len(other) == 0:
 584        return np.ones(len(path), bool)
 585    return cKDTree(other).query(path)[0] > distance

 588def huber_line(x: np.ndarray, y: np.ndarray, k: float = 1.345, iters: int = 30) -> tuple[float, float]:
 589    """Robust straight-line fit ``y ≈ a + b·x`` by Huber regression.
 590
 591    Iteratively reweighted least squares: residuals within ``k`` robust
 592    standard deviations (scale = 1.4826 × median absolute residual) get full
 593    weight, larger ones weight ``k·σ/|r|``, so outliers pull the line far less
 594    than in ordinary least squares.
 595
 596    Returns:
 597        ``(a, b)``; ``b = 0`` if ``x`` has no spread.
 598    """
 599    x, y = np.asarray(x, float), np.asarray(y, float)
 600    if np.ptp(x) == 0:
 601        return float(np.median(y)), 0.0
 602    X = np.stack([np.ones_like(x), x], 1)
 603    w = np.ones_like(y)
 604    beta = np.zeros(2)
 605    for _ in range(iters):
 606        sw = np.sqrt(w)
 607        new, *_ = np.linalg.lstsq(X * sw[:, None], y * sw, rcond=None)
 608        res = y - X @ new
 609        scale = 1.4826 * np.median(np.abs(res)) or 1e-9
 610        u = np.abs(res) / (k * scale)
 611        w = np.where(u <= 1, 1.0, 1.0 / np.maximum(u, 1e-12))
 612        if np.allclose(new, beta, atol=1e-6):
 613            break
 614        beta = new
 615    return float(new[0]), float(new[1])

 618def huber_location(y: np.ndarray, k: float = 1.345, iters: int = 30) -> float:
 619    """Robust average of ``y`` by Huber's M-estimator (see :func:`huber_line`).
 620
 621    Starts from the median; values more than ``k`` robust standard
 622    deviations away are down-weighted, so a minority of outliers (e.g.
 623    cross-sections that also caught a branch behind) barely move it.
 624    """
 625    y = np.asarray(y, float)
 626    m = float(np.median(y))
 627    for _ in range(iters):
 628        res = y - m
 629        scale = 1.4826 * np.median(np.abs(res)) or 1e-9
 630        u = np.abs(res) / (k * scale)
 631        w = np.where(u <= 1, 1.0, 1.0 / np.maximum(u, 1e-12))
 632        new = float(np.sum(w * y) / np.sum(w))
 633        if abs(new - m) < 1e-6:
 634            return new
 635        m = new
 636    return m

 639def scale_space_radius(grey: np.ndarray, points: np.ndarray, scales: tuple[float, float] = (1.5, 12.0),
 640                       window: int = 4, ratio: float = 1.2) -> np.ndarray:
 641    """Branch half-width at each point, by scale-space ridge detection.
 642
 643    The image is smoothed with Gaussians of width σ over a geometric range of
 644    scales. At each scale the larger-magnitude eigenvalue of the Hessian
 645    (curvature across a branch), multiplied by σ² (scale normalisation), is
 646    computed; its sign is ignored, so bark lighter than grass and bark
 647    darker than sky both count. For a bar of half-width *a* this normalised
 648    response peaks at σ = *a* (the maximum of 2u·φ(u) is at u = a/σ = 1), so
 649    the scale of the strongest response within ``window`` px of each point
 650    is taken as its half-width. On synthetic bars that are brighter than the
 651    background right to their edges, of half-width 3–12 px, the error is at
 652    most 0.5 px.
 653
 654    Real bark is not like that: a branch lit from one side is bright on that
 655    side and dark on the other, and its edges are darker than its middle.
 656    On such (Lambertian) bars this returns about 0.55–0.6 of the half-width,
 657    and on the development trees about half the bark's width, so it is no
 658    longer the default (see :func:`branch_edges`).
 659
 660    Only a box around the points (padded by 3σ) is filtered, to save time.
 661
 662    Args:
 663        grey: ``(H, W)`` float image.
 664        points: ``(N, 2)`` ``(row, col)`` points.
 665        scales: Smallest and largest σ searched (px).
 666        window: Search half-size around each point (px).
 667        ratio: Ratio between successive scales.
 668
 669    Returns:
 670        ``(N,)`` half-widths (px).
 671    """
 672    if len(points) == 0:
 673        return np.zeros(0)
 674    sig = scales[0] * ratio ** np.arange(int(np.log(scales[1] / scales[0]) / np.log(ratio)) + 1)
 675    pad = int(3 * sig[-1]) + window + 1
 676    r0, c0 = np.maximum(points.min(0) - pad, 0)
 677    r1, c1 = np.minimum(points.max(0) + pad + 1, grey.shape)
 678    crop = grey[r0:r1, c0:c1].astype(float)
 679    best_resp = np.full(len(points), -np.inf)
 680    best_sig = np.full(len(points), sig[0])
 681    pr, pc = points[:, 0] - r0, points[:, 1] - c0
 682    for s in sig:
 683        h = hessian_matrix(crop, sigma=s, order="rc", use_gaussian_derivatives=True)
 684        ev = hessian_matrix_eigvals(h)
 685        resp = ndi.maximum_filter(s * s * np.maximum(np.abs(ev[0]), np.abs(ev[1])), size=2 * window + 1)
 686        v = resp[pr, pc]
 687        better = v > best_resp
 688        best_resp[better], best_sig[better] = v[better], s
 689    return best_sig

 692def path_normals(path: np.ndarray, half: int = 6) -> np.ndarray:
 693    """Unit normals to a path, from the chord ``half`` points either side.
 694
 695    The chord ignores pixel-scale wiggles. The normal is the direction of
 696    travel turned by 90° to its left, ``(−d_col, d_row)``.
 697
 698    Args:
 699        path: ``(N, 2)`` ``(row, col)`` points in order.
 700        half: Chord half-length in points (shortened at the ends).
 701
 702    Returns:
 703        ``(N, 2)`` unit vectors ``(d_row, d_col)``; zero where the path does
 704        not move.
 705    """
 706    n = len(path)
 707    i = np.arange(n)
 708    d = (path[np.minimum(i + half, n - 1)] - path[np.maximum(i - half, 0)]).astype(float)
 709    size = np.hypot(d[:, 0], d[:, 1])[:, None]
 710    d = np.divide(d, size, out=np.zeros_like(d), where=size > 0)
 711    return np.stack([-d[:, 1], d[:, 0]], 1)

 714def straighten(image: np.ndarray, path: np.ndarray, half_width: int, order: int = 1) -> np.ndarray:
 715    """Sample an image across a path: one row per path point.
 716
 717    Row ``i`` holds the image along the normal at point ``i``
 718    (:func:`path_normals`), from ``−half_width`` to ``+half_width`` px, so
 719    the branch runs down the middle column. Samples outside the image take
 720    the nearest edge value.
 721
 722    Args:
 723        image: ``(H, W)`` or ``(H, W, C)`` array.
 724        path: ``(N, 2)`` ``(row, col)`` points.
 725        half_width: Reach either side of the path (px).
 726        order: Interpolation order (1 = bilinear, 0 = nearest).
 727
 728    Returns:
 729        ``(N, 2·half_width + 1)`` or ``(N, 2·half_width + 1, C)`` float array.
 730    """
 731    normals = path_normals(path)
 732    off = np.arange(-half_width, half_width + 1)[None, :]
 733    coords = [path[:, :1] + off * normals[:, :1], path[:, 1:] + off * normals[:, 1:]]
 734    img = np.asarray(image, float)
 735    if img.ndim == 2:
 736        return ndi.map_coordinates(img, coords, order=order, mode="nearest")
 737    return np.stack([ndi.map_coordinates(img[..., k], coords, order=order, mode="nearest")
 738                     for k in range(img.shape[2])], -1)

 741def _cumsum0(values: np.ndarray, axis: int) -> np.ndarray:
 742    """Cumulative sum along ``axis`` with a leading zero (so sums over i0..i1-1 are c[i1] − c[i0])."""
 743    pad = [(0, 0)] * values.ndim
 744    pad[axis] = (1, 0)
 745    return np.cumsum(np.pad(values, pad), axis=axis)

 748def profile_edges(profiles: np.ndarray, min_background: int = 3, min_half: int = 1) -> tuple[np.ndarray, np.ndarray]:
 749    """Where the branch starts and ends in each cross-section profile.
 750
 751    Each profile is modelled in three pieces and fitted by least squares:
 752    the background on one side (a constant colour), the branch (a quadratic
 753    in position, per colour channel) and the background on the other side
 754    (a constant). A branch lit from one side is bright on that side and dark
 755    on the other; the quadratic follows that shading across the whole branch,
 756    whereas an edge or ridge detector stops at the change from the lit to
 757    the shaded half. Every pair of change points is tried: the squared
 758    error of each piece comes from cumulative sums of the samples and their
 759    powers, so all pairs are scored at once. The branch must include the
 760    centre (the path).
 761
 762    On synthetic branches lit from the front or either side, of half-width
 763    3–9 px with the path up to 2 px off-centre, the half-width was found to
 764    within 0.5 px in 47 of 48 cases, and within 1 px in the last (a
 765    front-lit branch whose dark rim was as bright as the background).
 766    Where a shaded half is as dark as the background next to it, it can be
 767    left out; the robust fit along the leader (:func:`fit_leader_radius`)
 768    absorbs such points.
 769
 770    Args:
 771        profiles: ``(M, N)`` or ``(M, N, C)`` samples across the branch, ``N``
 772            odd, centred on the path (e.g. from :func:`straighten`).
 773        min_background: Fewest background samples on each side.
 774        min_half: The branch reaches at least this many samples either side
 775            of the centre.
 776
 777    Returns:
 778        ``(first, last)``: ``(M,)`` int offsets from the centre (px) of the
 779        first and last branch samples. The half-width is
 780        ``(last − first + 1) / 2``.
 781    """
 782    p = np.asarray(profiles, float)
 783    if p.ndim == 2:
 784        p = p[..., None]
 785    m, n, _ = p.shape
 786    half = n // 2
 787    if m == 0:
 788        return np.zeros(0, int), np.zeros(0, int)
 789    x = (np.arange(n) - half) / max(half, 1)                       # in [-1, 1], for conditioning
 790    firsts = np.arange(min_background, half - min_half + 1)
 791    lasts = np.arange(half + min_half, n - min_background)
 792    if len(firsts) == 0 or len(lasts) == 0:
 793        raise ValueError(f"profiles of {n} samples are too short for {min_background} background "
 794                         f"and {min_half} branch samples on each side")
 795    a, b = (g.ravel() for g in np.meshgrid(firsts, lasts, indexing="ij"))
 796    sx = _cumsum0(np.stack([x ** k for k in range(5)]), 1)          # (5, n+1): sums of x^k
 797    sxy = _cumsum0(np.stack([x ** k for k in range(3)])[:, None, :, None] * p[None], 2)  # (3, m, n+1, C)
 798    syy = _cumsum0((p ** 2).sum(-1), 1)                            # (m, n+1)
 799
 800    def constant_sse(i0: np.ndarray, i1: np.ndarray) -> np.ndarray:
 801        """Squared error of the best constant over samples i0..i1-1, per profile and pair."""
 802        s = sxy[0][:, i1] - sxy[0][:, i0]
 803        return syy[:, i1] - syy[:, i0] - (s ** 2).sum(-1) / (i1 - i0)
 804
 805    # Quadratic over a..b: normal equations G β = r, error = Σy² − rᵀG⁻¹r.
 806    i0, i1 = a, b + 1
 807    gram = np.stack([np.stack([sx[j + k][i1] - sx[j + k][i0] for k in range(3)], -1) for j in range(3)], -2)
 808    r = np.stack([sxy[j][:, i1] - sxy[j][:, i0] for j in range(3)], 2)   # (m, pairs, 3, C)
 809    solved = np.einsum("pjk,mpkc->mpjc", np.linalg.inv(gram), r)
 810    quadratic = syy[:, i1] - syy[:, i0] - (r * solved).sum((2, 3))
 811    cost = constant_sse(np.zeros_like(a), a) + quadratic + constant_sse(b + 1, np.full_like(b, n))
 812    best = np.argmin(cost, 1)
 813    return a[best] - half, b[best] - half
 814

 816def branch_edges(rgb: np.ndarray, path: np.ndarray, half_width: int = 20,
 817                 along: int = 3) -> tuple[np.ndarray, np.ndarray]:
 818    """Both edges of a branch at each point of its path, from the colour image.
 819
 820    The image is sampled across the path (:func:`straighten`), each
 821    cross-section is averaged with its ``along`` neighbours either side, and
 822    the edges are found by :func:`profile_edges`.
 823
 824    Args:
 825        rgb: ``(H, W, 3)`` colour image.
 826        path: ``(N, 2)`` points along the branch.
 827        half_width: Reach of each cross-section either side of the path (px).
 828        along: Cross-sections averaged either side of each point.
 829
 830    Returns:
 831        ``(first, last)``: ``(N,)`` int offsets (px) of the branch's edges
 832        along each point's normal (:func:`path_normals`).
 833    """
 834    if len(path) == 0:
 835        return np.zeros(0, int), np.zeros(0, int)
 836    samples = straighten(rgb, path, half_width)
 837    if along > 0:
 838        samples = ndi.uniform_filter1d(samples, 2 * along + 1, axis=0, mode="nearest")
 839    return profile_edges(samples)

 842def fit_leader_radius(path: np.ndarray, measured: np.ndarray, fork_radius: float, widening: float = 0.35,
 843                      length: float = 12.0, start: float = 1.5, part: str = "left",
 844                      min_valid: float = 2.5, min_points: int = 8) -> np.ndarray:
 845    """A leader's drawing radius: its own width, widened near the fork.
 846
 847    ``r(s) = c · (1 + widening · exp(−s / (length · R)))``, where ``s`` is the
 848    distance along the leader from the fork and ``R`` the trunk's radius at
 849    the fork. The shape is shared by all leaders (see
 850    :attr:`GuidedParams.fork_widening`), because one leader's widths are
 851    too noisy to fit its own taper: with a free straight taper, half of
 852    the development trees' leaders came out widening upwards. Only the
 853    leader's own width ``c`` is fitted, as a robust (Huber) average of
 854    ``measured / (1 + widening · exp(…))`` over the points at least
 855    ``start · R`` from the fork. Nearer, the cross-section cuts through the
 856    top of the trunk. Measurements at or below ``min_valid`` (failed edges)
 857    or nan (no measurement, e.g. a cross-section that could include the
 858    other leader, see :func:`clear_of`) are ignored. With fewer than
 859    ``min_points`` usable measurements,
 860    :data:`FALLBACK_RADIUS` is used for ``c``. The result is clipped to
 861    :data:`RADIUS_LIMITS`.
 862
 863    Args:
 864        path: ``(N, 2)`` leader path starting at the fork.
 865        measured: ``(N,)`` measured half-widths (px), nan where not measured.
 866        fork_radius: The trunk's radius at the fork, ``R`` (px).
 867        widening: Extra width at the fork, as a fraction of ``c``.
 868        length: Distance over which the widening falls by a factor e, in
 869            trunk radii.
 870        start: Nearest distance from the fork used to fit ``c``, in trunk
 871            radii.
 872        part: ``"left"`` or ``"right"`` (for the limits and fallback).
 873
 874    Returns:
 875        ``(N,)`` radii to draw.
 876    """
 877    lo, hi = RADIUS_LIMITS[part]
 878    if len(path) == 0:
 879        return np.zeros(0)
 880    s = arc_length(path)
 881    shape = 1 + widening * np.exp(-s / max(length * fork_radius, 1e-9))
 882    use = (measured > min_valid) & (s >= start * fork_radius)
 883    level = huber_location(measured[use] / shape[use]) if use.sum() >= min_points else FALLBACK_RADIUS[part]
 884    return np.clip(level * shape, lo, hi)

 887def fit_taper(path: np.ndarray, measured: np.ndarray, part: str,
 888              min_valid: float = 2.5, min_points: int = 8) -> np.ndarray:
 889    """Smooth, tapering radius along one part from noisy width measurements.
 890
 891    Width measured from depth is unreliable point by point: depth gaps give
 892    near-zero widths (drawn as thin lines), and ground or background merging
 893    with the branch gives large blobs. Treating the measurements as noisy
 894    observations, radius is modelled as linear in arc length along the path
 895    (a branch tapers gradually) and fitted by :func:`huber_line`, ignoring
 896    measurements at or below ``min_valid`` (gaps). A fit that widens upwards
 897    is physically implausible, so it is replaced by the median width
 898    (constant). The result is clipped to
 899    :data:`RADIUS_LIMITS`. With fewer than ``min_points`` usable
 900    measurements, :data:`FALLBACK_RADIUS` is used.
 901
 902    Args:
 903        path: ``(N, 2)`` path points, in order.
 904        measured: ``(N,)`` measured half-widths at those points (px).
 905        part: ``"trunk"``, ``"left"`` or ``"right"``.
 906
 907    Returns:
 908        ``(N,)`` radii to draw.
 909    """
 910    lo, hi = RADIUS_LIMITS[part]
 911    if len(path) == 0:
 912        return np.zeros(0)
 913    s = arc_length(path)
 914    ok = measured > min_valid
 915    if ok.sum() < min_points:
 916        return np.full(len(path), FALLBACK_RADIUS[part])
 917    a, b = huber_line(s[ok], measured[ok])
 918    if b > 0:
 919        # Branches do not widen upwards: use a constant (robust) width instead.
 920        a, b = float(np.median(measured[ok])), 0.0
 921    return np.clip(a + b * s, lo, hi)

 924def arc_length(path: np.ndarray) -> np.ndarray:
 925    """Distance (px) along ``path`` from its first point to each point."""
 926    if len(path) < 2:
 927        return np.zeros(len(path))
 928    return np.concatenate([[0.0], np.cumsum(np.hypot(*np.diff(path, axis=0).T))])

 931def outward_normal(path: np.ndarray, other: np.ndarray, reach: float) -> np.ndarray:
 932    """Unit normal to a leader's direction near the fork, on its outer side.
 933
 934    The direction is the chord from the fork to the point ``reach`` px along
 935    the path, which ignores pixel-scale wiggles. Of its two normals, the one
 936    pointing from the other leader (at the same distance along it) towards
 937    this one is returned, i.e. away from the crotch between the leaders.
 938
 939    Args:
 940        path: ``(N, 2)`` leader path starting at the fork.
 941        other: ``(M, 2)`` the other leader's path, also starting at the fork.
 942        reach: Chord length (px).
 943
 944    Returns:
 945        ``(2,)`` unit vector ``(d_row, d_col)``, or zeros if the path does
 946        not move away from the fork.
 947    """
 948    i = min(int(np.searchsorted(arc_length(path), reach)), len(path) - 1)
 949    j = min(int(np.searchsorted(arc_length(other), reach)), len(other) - 1)
 950    d = (path[i] - path[0]).astype(float)
 951    n = np.array([-d[1], d[0]])
 952    if n @ (path[i] - other[j]) < 0:
 953        n = -n
 954    size = np.hypot(*n)
 955    return n / size if size > 0 else np.zeros(2)

 958def shoulder_fill(shape: tuple[int, int], leader: np.ndarray, other: np.ndarray, radii: np.ndarray,
 959                  fork_radius: float, length: float) -> np.ndarray:
 960    """Pixels that fill the notch ("shoulder") beside a leader where it leaves the trunk.
 961
 962    Each leader's radius is one taper fitted along its whole length
 963    (:func:`fit_taper`), so a thin leader starts abruptly out of the round
 964    end of a much wider trunk, leaving a notch on its outer side. In the
 965    winter depth images the wood fills that notch: the trunk's edge runs
 966    into the leader's outer edge. So on the leader's outer side
 967    (:func:`outward_normal`), the mask is filled out to the convex hull of
 968    the trunk's end (its disc of radius ``R`` at the fork) and the leader's
 969    first ``length`` px. Its edge is the straight line from the trunk's edge
 970    to the leader's edge ``length`` px up the leader.
 971
 972    The fill never reaches outside that hull, so it cannot widen a straight
 973    trunk, and the crotch (between the leaders) is left as drawn. Other
 974    shapes were tried on the development trees and rejected (see
 975    ``docs/results/fork_shoulders/``). For example, widening both sides of
 976    each leader also filled the crotch, where many of the added pixels were
 977    not wood in depth; and widening the leader's discs smoothly into the
 978    trunk (a flare) bulged past the trunk's straight edges on a synthetic
 979    tree of known shape.
 980
 981    Args:
 982        shape: Image shape ``(H, W)``.
 983        leader: ``(N, 2)`` leader path starting at the fork.
 984        other: ``(M, 2)`` the other leader's path, to tell the outer side.
 985        radii: ``(N,)`` the leader's drawing radii (px).
 986        fork_radius: The trunk's drawing radius at the fork, ``R`` (px).
 987        length: How far along the leader the fill reaches (px); 0 or less
 988            gives an empty mask.
 989
 990    Returns:
 991        ``(H, W)`` bool mask of the fill, to be added to the drawn branches.
 992    """
 993    out = np.zeros(shape, bool)
 994    if length <= 0 or len(leader) == 0:
 995        return out
 996    base = leader[arc_length(leader) <= length]       # a prefix: arc length only grows
 997    fork = leader[0]
 998    # Work in a box around the fork that holds every disc (and so their hull).
 999    pad = int(np.ceil(max(fork_radius, radii[:len(base)].max()))) + 2
1000    lo = np.maximum(np.minimum(base.min(0), fork) - pad, 0)
1001    hi = np.minimum(np.maximum(base.max(0), fork) + pad + 1, shape)
1002    box = tuple(int(v) for v in hi - lo)
1003    discs = np.zeros(box, bool)
1004    for (y, x), rad in [(fork, fork_radius), *zip(base, radii)]:
1005        rr, cc = draw_disk((y - lo[0], x - lo[1]), rad, shape=box)
1006        discs[rr, cc] = True
1007    n = outward_normal(leader, other, max(length, 10.0))
1008    yy, xx = np.indices(box)
1009    outer = (yy + lo[0] - fork[0]) * n[0] + (xx + lo[1] - fork[1]) * n[1] >= 0
1010    out[lo[0]:hi[0], lo[1]:hi[1]] = convex_hull_image(discs) & outer
1011    return out

1014def fill_shoulders(gt: WinterGT, shoulder_length: float) -> np.ndarray:
1015    """Both leaders' :func:`shoulder_fill` for a traced tree with fitted radii.
1016
1017    Args:
1018        gt: Result of :func:`guided_gt` (its paths and ``radii`` are used).
1019        shoulder_length: Reach of the fill, in multiples of the trunk's
1020            radius at the fork (:attr:`GuidedParams.shoulder_length`).
1021
1022    Returns:
1023        Bool mask the shape of ``gt.tree_mask``.
1024    """
1025    fork_r = _fork_radius(gt.radii)

1027    for side, leader, other in (("left", gt.left, gt.right), ("right", gt.right, gt.left)):
1028        out |= shoulder_fill(out.shape, leader, other, gt.radii[side], fork_r, shoulder_length * fork_r)

1032def end_direction(path: np.ndarray, length: float) -> np.ndarray:
1033    """Unit vector pointing out of a path at its last point.
1034
1035    The direction is the chord to the last point from the point about
1036    ``length`` px before it (the first point, if the path is shorter), which
1037    ignores pixel-scale wiggles.
1038
1039    Args:
1040        path: ``(N, 2)`` path points, in order.
1041        length: Chord length (px).
1042
1043    Returns:
1044        ``(2,)`` unit vector ``(d_row, d_col)``, or zeros if the path has no length.
1045    """
1046    if len(path) < 2:
1047        return np.zeros(2)
1048    back = arc_length(path)
1049    back = back[-1] - back                              # distance back from the last point
1050    d = (path[-1] - path[int(np.argmin(np.abs(back - length)))]).astype(float)
1051    size = np.hypot(*d)
1052    return d / size if size > 0 else np.zeros(2)

1055def end_cut(path: np.ndarray, radius: float) -> tuple[np.ndarray, np.ndarray] | None:
1056    """A flat end for a path drawn as discs: the line through its last point, square to it.
1057
1058    Drawn as a union of discs, a path ends in a half disc of its radius
1059    there. Pixels beyond this line (see
1060    :attr:`treeskel.winter_gt.WinterGT.trunk_cuts`) are not drawn, which
1061    squares the end off. The direction is taken over the path's last
1062    ``radius`` px (:func:`end_direction`).
1063
1064    Args:
1065        path: ``(N, 2)`` path points, ending at the end to cut.
1066        radius: The drawing radius at that end (px).
1067
1068    Returns:
1069        ``(point, outward direction)`` as float arrays, or None if the path
1070        has no direction there.
1071    """
1072    d = end_direction(path, float(radius))
1073    return (path[-1].astype(float), d) if d.any() else None

1076def fork_junction(gt: WinterGT, reach: float) -> np.ndarray:
1077    """Pixels joining the trunk's flat top to each leader's outer edge with a straight side.
1078
1079    With the trunk cut flat at the fork (:func:`end_cut`), each leader
1080    is joined to the trunk on its outer side (:func:`outward_normal`): the
1081    join is the convex hull of the trunk's top from the fork to its edge on
1082    that side, and of the leader's discs up to ``reach`` trunk radii along
1083    it, kept to the outer side of the leader's direction. Its outer edge is
1084    then the straight line from the trunk's edge to the leader's edge, and
1085    the crotch between the leaders is left as the leaders' own discs draw
1086    it: a V, not the round top of the trunk. The shoulder fill
1087    (:func:`shoulder_fill`) is similar but takes the trunk's round end disc
1088    into the hull, so the round top stays.
1089
1090    Args:
1091        gt: A guided result with fitted ``radii``; its trunk ends, and both
1092            leaders start, at the fork.
1093        reach: How far up each leader the join reaches, in trunk radii at
1094            the fork (:attr:`GuidedParams.junction_reach`); 0 or less gives
1095            an empty mask.
1096
1097    Returns:
1098        ``(H, W)`` bool mask of the join, to be added to the drawn branches.
1099    """
1100    shape = gt.tree_mask.shape
1101    out = np.zeros(shape, bool)
1102    if reach <= 0 or len(gt.trunk) < 2 or len(gt.left) == 0 or len(gt.right) == 0:
1103        return out
1104    radius = _fork_radius(gt.radii)
1105    up = end_direction(gt.trunk, radius)
1106    if not up.any():
1107        return out
1108    fork = gt.trunk[-1]
1109    across = np.array([-up[1], up[0]])                   # square to the trunk, along its flat top
1110    for side, other in (("left", gt.right), ("right", gt.left)):
1111        leader, radii = getattr(gt, side), gt.radii[side]
1112        outer = outward_normal(leader, other, max(reach * radius, 10.0))
1113        if not outer.any():
1114            continue
1115        corner = fork + radius * (across if across @ outer >= 0 else -across)   # the trunk's edge on this side
1116        base = arc_length(leader) <= reach * radius       # a prefix: arc length only grows
1117        # Work in a box around the fork that holds the top and every disc (and so their hull).
1118        pad = int(np.ceil(radii[base].max())) + 2
1119        points = np.vstack([fork, corner, leader[base]])
1120        lo = np.maximum(np.floor(points.min(0)).astype(int) - pad, 0)
1121        hi = np.minimum(np.ceil(points.max(0)).astype(int) + pad + 1, shape)
1122        if np.any(hi <= lo):
1123            continue
1124        box = tuple(int(v) for v in hi - lo)
1125        parts = np.zeros(box, bool)
1126        for (y, x), rad in zip(leader[base], radii[base]):
1127            rr, cc = draw_disk((y - lo[0], x - lo[1]), rad, shape=box)
1128            parts[rr, cc] = True
1129        end = np.round(corner).astype(int)
1130        rr, cc = draw_line(int(fork[0] - lo[0]), int(fork[1] - lo[1]), int(end[0] - lo[0]), int(end[1] - lo[1]))
1131        inside = (rr >= 0) & (rr < box[0]) & (cc >= 0) & (cc < box[1])
1132        parts[rr[inside], cc[inside]] = True
1133        yy, xx = np.indices(box)
1134        keep = (yy + lo[0] - fork[0]) * outer[0] + (xx + lo[1] - fork[1]) * outer[1] >= 0
1135        out[lo[0]:hi[0], lo[1]:hi[1]] |= convex_hull_image(parts) & keep
1136    return out

1144def insert_waypoint(clicks: Clicks, gt: WinterGT, point: Point) -> Clicks:
1145    """Add a correcting click to the part of the trace it is nearest to.
1146
1147    The point joins the trunk, left or right control points, whichever traced
1148    path passes closest to it, at the position matching its place along that
1149    path. The trunk's root and fork, and the leaders' tips, stay fixed.
1150
1151    Args:
1152        clicks: Current complete clicks.
1153        gt: The current trace (from :func:`guided_gt`).
1154        point: The new ``(row, col)`` click.
1155
1156    Returns:
1157        New :class:`Clicks` with the waypoint inserted.
1158    """
1159    p = np.asarray(point)
1160    best = None
1161    for name in ("trunk", "left", "right"):
1162        path = getattr(gt, name)
1163        if len(path):
1164            d = np.hypot(*(path - p).T)
1165            i = int(np.argmin(d))
1166            if best is None or d[i] < best[0]:
1167                best = (d[i], name, i, path)
1168    _, name, idx, path = best
1169    ctrl = list(getattr(clicks, name))
1170
1171    def pos(q: Point) -> int:
1172        """Index of the path point nearest to ``q``."""
1173        return int(np.argmin(np.hypot(*(path - np.asarray(q)).T)))
1174
1175    # Insert before the first control point that lies further along the path.
1176    # The trunk's first point (root) is fixed, so start after it.
1177    start = 1 if name == "trunk" else 0
1178    k = next((j for j in range(start, len(ctrl)) if pos(ctrl[j]) > idx), len(ctrl))
1179    if name == "trunk":
1180        k = min(max(k, 1), len(ctrl) - 1)   # keep root first and fork last
1181    else:
1182        k = min(k, len(ctrl) - 1)           # keep the tip last
1183    ctrl.insert(k, (int(point[0]), int(point[1])))
1184    new = Clicks(**{**clicks.__dict__})
1185    setattr(new, name, ctrl)
1186    return new

1189def check_clicks(c: Clicks, min_rise: int = 40, min_spread: int = 40) -> list[str]:
1190    """Geometric sanity checks on a tree's clicks (image rows grow downwards).
1191
1192    Flags click-order slips that cannot be right for a Tatura V tree: the fork
1193    not clearly (10 px) above the root, a tip not clearly above the fork, or the two tips
1194    almost on top of each other. It cannot catch an accepted trace that
1195    follows the wrong branch; that needs looking at the overlay.
1196
1197    Returns:
1198        Human-readable problems (empty if none, or if skipped/incomplete).
1199    """
1200    if c.skip or not c.complete:
1201        return []
1202    c = c.normalised()
1203    (rr, _), (fr, _) = c.trunk[0], c.fork
1204    issues = []
1205    if rr - fr < 10 and "splits at ground" not in c.note:
1206        issues.append(f"fork only {rr - fr} px above the root (double click, or a tree "
1207                      "that splits at the ground?)")
1208    for side in ("left", "right"):
1209        tip = getattr(c, side)[-1]
1210        if fr - tip[0] < min_rise:
1211            issues.append(f"{side} tip only {fr - tip[0]} px above the fork")
1212    if c.right[-1][1] - c.left[-1][1] < min_spread:
1213        issues.append("leader tips are close together")
1214    return issues

1240def main(argv: Sequence[str] | None = None) -> int:
1241    """Render guided ground truth for every annotated tree.
1242
1243    Usage: ``python -m treeskel.guided_gt DATA_DIR --clicks annotations/winter_clicks.json
1244    --out outputs/winter_gt_guided [--overlays] [--rows 5 6] [--trees R05N12]
1245    [--jobs N]``.
1246
1247    Most of the time per tree (about 1 s) is the Frangi filter in the cost
1248    map, so trees are processed in parallel, one per CPU core by default,
1249    and progress is printed as they finish.
1250    """
1251    import os
1252    import time
1253    from concurrent.futures import ProcessPoolExecutor
1254
1255    from treeskel.io import index_dataset
1256
1257    ap = argparse.ArgumentParser(prog="python -m treeskel.guided_gt", description=__doc__.splitlines()[0])
1258    ap.add_argument("data_dir")
1259    ap.add_argument("--clicks", default="annotations/winter_clicks.json")
1260    ap.add_argument("--out", default="outputs/winter_gt_guided", help="output folder (git-ignored)")
1261    ap.add_argument("--overlays", action="store_true", help="also save <tree>_overlay.jpg")
1262    ap.add_argument("--rows", type=int, nargs="+", help="only trees in these rows")
1263    ap.add_argument("--trees", nargs="+", help="only these tree ids")
1264    ap.add_argument("--jobs", type=int, default=os.cpu_count() or 1,
1265                    help="trees processed in parallel (default: number of CPU cores)")
1266    args = ap.parse_args(argv)
1267
1268    clicks = load_clicks(args.clicks)
1269    trees = {t.tree_id: t for t in index_dataset(args.data_dir).trees}
1270    out = Path(args.out)
1271    out.mkdir(parents=True, exist_ok=True)
1272    params = GuidedParams()
1273    (out / "params.json").write_text(json.dumps(asdict(params), indent=2))   # the settings, beside the masks
1274
1275    # The clicked trees asked for; trees skipped in the click tool or not finished are left out.
1276    wanted = sorted(clicks)
1277    if args.rows:
1278        wanted = [t for t in wanted if int(t[1:3]) in args.rows]
1279    if args.trees:
1280        wanted = [t for t in wanted if t in set(args.trees)]
1281    skipped = [t for t in wanted if clicks[t].skip or not clicks[t].complete]
1282    missing = [t for t in wanted if t not in skipped and t not in trees]
1283    jobs = [(trees[t], clicks[t], params, out, args.overlays)
1284            for t in wanted if t not in skipped and t not in missing]
1285
1286    rows, failed = [], []
1287    t0 = time.time()
1288    step = max(1, min(25, len(jobs) // 10))
1289
1290    def progress(done: int) -> None:
1291        """Print progress every ``step`` trees (about 10%, at most 25), with the time left."""
1292        if done % step == 0 or done == len(jobs):
1293            el = time.time() - t0
1294            eta = el / done * (len(jobs) - done)
1295            print(f"  {done}/{len(jobs)} trees, {el:.0f} s elapsed, about {eta:.0f} s left", flush=True)
1296
1297    print(f"Rendering {len(jobs)} trees using {max(1, min(args.jobs, len(jobs)))} process(es)...", flush=True)
1298    # Trace and draw each tree, in worker processes when there is more than one core and tree.
1299    if args.jobs > 1 and len(jobs) > 1:
1300        with ProcessPoolExecutor(max_workers=args.jobs) as ex:
1301            for i, (_, row, f) in enumerate(ex.map(_render_one, jobs, chunksize=4), 1):
1302                rows.append(row)
1303                failed += f
1304                progress(i)
1305    else:
1306        for i, job in enumerate(jobs, 1):
1307            _, row, f = _render_one(job)
1308            rows.append(row)
1309            failed += f
1310            progress(i)
1311
1312    if rows:
1313        with open(out / "summary.csv", "w", newline="") as f:
1314            w = csv.DictWriter(f, fieldnames=list(dict.fromkeys(k for r in rows for k in r)))
1315            w.writeheader()
1316            w.writerows(rows)
1317    # Clicks that look like mistakes (e.g. a fork right at the root) are listed for checking by eye.
1318    suspect = {t: check_clicks(clicks[t]) for t in wanted if check_clicks(clicks[t])}
1319    for tid, why in sorted(suspect.items()):
1320        print(f"Check clicks for {tid}: {'; '.join(why)}")
1321    print(f"Rendered {len(rows)} trees in {time.time() - t0:.0f} s; {len(skipped)} skipped or "
1322          f"incomplete; {len(missing)} not found in {args.data_dir}. Results in {out}")
1323    report_failed(failed)
1324    return 1 if failed else 0

420

422    a residual (the path's sideways wiggle). Only the residual is smoothed,
423    with a Gaussian of width ``sigma`` (in path steps, about pixels), after
424    an odd reflection at each end, which keeps the residual zero there. Real
425    bends are kept, pixel-scale zig-zags are removed, and the result is
426    re-drawn as a connected 8-connected pixel path.

438    step = np.hypot(*np.diff(p, axis=0).T)

def huber_line( x: numpy.ndarray, y: numpy.ndarray, k: float = 1.345, iters: int = 30) -> tuple[float, float]: 
589def huber_line(x: np.ndarray, y: np.ndarray, k: float = 1.345, iters: int = 30) -> tuple[float, float]:
590    """Robust straight-line fit ``y ≈ a + b·x`` by Huber regression.
591
592    Iteratively reweighted least squares: residuals within ``k`` robust
593    standard deviations (scale = 1.4826 × median absolute residual) get full
594    weight, larger ones weight ``k·σ/|r|``, so outliers pull the line far less
595    than in ordinary least squares.
596
597    Returns:
598        ``(a, b)``; ``b = 0`` if ``x`` has no spread.
599    """
600    x, y = np.asarray(x, float), np.asarray(y, float)
601    if np.ptp(x) == 0:
602        return float(np.median(y)), 0.0
603    X = np.stack([np.ones_like(x), x], 1)
604    w = np.ones_like(y)
605    beta = np.zeros(2)
606    for _ in range(iters):
607        sw = np.sqrt(w)
608        new, *_ = np.linalg.lstsq(X * sw[:, None], y * sw, rcond=None)
609        res = y - X @ new
610        scale = 1.4826 * np.median(np.abs(res)) or 1e-9
611        u = np.abs(res) / (k * scale)
612        w = np.where(u <= 1, 1.0, 1.0 / np.maximum(u, 1e-12))
613        if np.allclose(new, beta, atol=1e-6):
614            break
615        beta = new
616    return float(new[0]), float(new[1])

640def scale_space_radius(grey: np.ndarray, points: np.ndarray, scales: tuple[float, float] = (1.5, 12.0),
641                       window: int = 4, ratio: float = 1.2) -> np.ndarray:
642    """Branch half-width at each point, by scale-space ridge detection.
643
644    The image is smoothed with Gaussians of width σ over a geometric range of
645    scales. At each scale the larger-magnitude eigenvalue of the Hessian
646    (curvature across a branch), multiplied by σ² (scale normalisation), is
647    computed; its sign is ignored, so bark lighter than grass and bark
648    darker than sky both count. For a bar of half-width *a* this normalised
649    response peaks at σ = *a* (the maximum of 2u·φ(u) is at u = a/σ = 1), so
650    the scale of the strongest response within ``window`` px of each point
651    is taken as its half-width. On synthetic bars that are brighter than the
652    background right to their edges, of half-width 3–12 px, the error is at
653    most 0.5 px.
654
655    Real bark is not like that: a branch lit from one side is bright on that
656    side and dark on the other, and its edges are darker than its middle.
657    On such (Lambertian) bars this returns about 0.55–0.6 of the half-width,
658    and on the development trees about half the bark's width, so it is no
659    longer the default (see :func:`branch_edges`).
660
661    Only a box around the points (padded by 3σ) is filtered, to save time.
662
663    Args:
664        grey: ``(H, W)`` float image.
665        points: ``(N, 2)`` ``(row, col)`` points.
666        scales: Smallest and largest σ searched (px).
667        window: Search half-size around each point (px).
668        ratio: Ratio between successive scales.
669
670    Returns:
671        ``(N,)`` half-widths (px).
672    """
673    if len(points) == 0:
674        return np.zeros(0)
675    sig = scales[0] * ratio ** np.arange(int(np.log(scales[1] / scales[0]) / np.log(ratio)) + 1)
676    pad = int(3 * sig[-1]) + window + 1
677    r0, c0 = np.maximum(points.min(0) - pad, 0)

683    for s in sig:

688        better = v > best_resp
689        best_resp[better], best_sig[better] = v[better], s

750    """Where the branch starts and ends in each cross-section profile.
751
752    Each profile is modelled in three pieces and fitted by least squares:
753    the background on one side (a constant colour), the branch (a quadratic
754    in position, per colour channel) and the background on the other side
755    (a constant). A branch lit from one side is bright on that side and dark
756    on the other; the quadratic follows that shading across the whole branch,
757    whereas an edge or ridge detector stops at the change from the lit to
758    the shaded half. Every pair of change points is tried: the squared
759    error of each piece comes from cumulative sums of the samples and their
760    powers, so all pairs are scored at once. The branch must include the
761    centre (the path).
762
763    On synthetic branches lit from the front or either side, of half-width
764    3–9 px with the path up to 2 px off-centre, the half-width was found to
765    within 0.5 px in 47 of 48 cases, and within 1 px in the last (a
766    front-lit branch whose dark rim was as bright as the background).

780        first and last branch samples. The half-width is

787    half = n // 2
788    if m == 0:
789        return np.zeros(0, int), np.zeros(0, int)
790    x = (np.arange(n) - half) / max(half, 1)                       # in [-1, 1], for conditioning
791    firsts = np.arange(min_background, half - min_half + 1)
792    lasts = np.arange(half + min_half, n - min_background)
793    if len(firsts) == 0 or len(lasts) == 0:
794        raise ValueError(f"profiles of {n} samples are too short for {min_background} background "
795                         f"and {min_half} branch samples on each side")

797    sx = _cumsum0(np.stack([x ** k for k in range(5)]), 1)          # (5, n+1): sums of x^k
798    sxy = _cumsum0(np.stack([x ** k for k in range(3)])[:, None, :, None] * p[None], 2)  # (3, m, n+1, C)
799    syy = _cumsum0((p ** 2).sum(-1), 1)                            # (m, n+1)
800
801    def constant_sse(i0: np.ndarray, i1: np.ndarray) -> np.ndarray:
802        """Squared error of the best constant over samples i0..i1-1, per profile and pair."""
803        s = sxy[0][:, i1] - sxy[0][:, i0]
804        return syy[:, i1] - syy[:, i0] - (s ** 2).sum(-1) / (i1 - i0)

806    # Quadratic over a..b: normal equations G β = r, error = Σy² − rᵀG⁻¹r.
807    i0, i1 = a, b + 1
808    gram = np.stack([np.stack([sx[j + k][i1] - sx[j + k][i0] for k in range(3)], -1) for j in range(3)], -2)

811    quadratic = syy[:, i1] - syy[:, i0] - (r * solved).sum((2, 3))
812    cost = constant_sse(np.zeros_like(a), a) + quadratic + constant_sse(b + 1, np.full_like(b, n))
813    best = np.argmin(cost, 1)

1077def fork_junction(gt: WinterGT, reach: float) -> np.ndarray:
1078    """Pixels joining the trunk's flat top to each leader's outer edge with a straight side.
1079
1080    With the trunk cut flat at the fork (:func:`end_cut`), each leader
1081    is joined to the trunk on its outer side (:func:`outward_normal`): the
1082    join is the convex hull of the trunk's top from the fork to its edge on
1083    that side, and of the leader's discs up to ``reach`` trunk radii along
1084    it, kept to the outer side of the leader's direction. Its outer edge is
1085    then the straight line from the trunk's edge to the leader's edge, and
1086    the crotch between the leaders is left as the leaders' own discs draw
1087    it: a V, not the round top of the trunk. The shoulder fill
1088    (:func:`shoulder_fill`) is similar but takes the trunk's round end disc
1089    into the hull, so the round top stays.
1090
1091    Args:
1092        gt: A guided result with fitted ``radii``; its trunk ends, and both
1093            leaders start, at the fork.
1094        reach: How far up each leader the join reaches, in trunk radii at
1095            the fork (:attr:`GuidedParams.junction_reach`); 0 or less gives
1096            an empty mask.
1097
1098    Returns:
1099        ``(H, W)`` bool mask of the join, to be added to the drawn branches.
1100    """
1101    shape = gt.tree_mask.shape
1102    out = np.zeros(shape, bool)
1103    if reach <= 0 or len(gt.trunk) < 2 or len(gt.left) == 0 or len(gt.right) == 0:
1104        return out
1105    radius = _fork_radius(gt.radii)
1106    up = end_direction(gt.trunk, radius)
1107    if not up.any():
1108        return out
1109    fork = gt.trunk[-1]
1110    across = np.array([-up[1], up[0]])                   # square to the trunk, along its flat top
1111    for side, other in (("left", gt.right), ("right", gt.left)):
1112        leader, radii = getattr(gt, side), gt.radii[side]
1113        outer = outward_normal(leader, other, max(reach * radius, 10.0))
1114        if not outer.any():
1115            continue
1116        corner = fork + radius * (across if across @ outer >= 0 else -across)   # the trunk's edge on this side
1117        base = arc_length(leader) <= reach * radius       # a prefix: arc length only grows
1118        # Work in a box around the fork that holds the top and every disc (and so their hull).
1119        pad = int(np.ceil(radii[base].max())) + 2
1120        points = np.vstack([fork, corner, leader[base]])
1121        lo = np.maximum(np.floor(points.min(0)).astype(int) - pad, 0)
1122        hi = np.minimum(np.ceil(points.max(0)).astype(int) + pad + 1, shape)
1123        if np.any(hi <= lo):
1124            continue
1125        box = tuple(int(v) for v in hi - lo)
1126        parts = np.zeros(box, bool)
1127        for (y, x), rad in zip(leader[base], radii[base]):
1128            rr, cc = draw_disk((y - lo[0], x - lo[1]), rad, shape=box)
1129            parts[rr, cc] = True
1130        end = np.round(corner).astype(int)
1131        rr, cc = draw_line(int(fork[0] - lo[0]), int(fork[1] - lo[1]), int(end[0] - lo[0]), int(end[1] - lo[1]))
1132        inside = (rr >= 0) & (rr < box[0]) & (cc >= 0) & (cc < box[1])
1133        parts[rr[inside], cc[inside]] = True
1134        yy, xx = np.indices(box)
1135        keep = (yy + lo[0] - fork[0]) * outer[0] + (xx + lo[1] - fork[1]) * outer[1] >= 0
1136        out[lo[0]:hi[0], lo[1]:hi[1]] |= convex_hull_image(parts) & keep
1137    return out

1146    """Add a correcting click to the part of the trace it is nearest to.
1147
1148    The point joins the trunk, left or right control points, whichever traced
1149    path passes closest to it, at the position matching its place along that
1150    path. The trunk's root and fork, and the leaders' tips, stay fixed.
1151
1152    Args:
1153        clicks: Current complete clicks.
1154        gt: The current trace (from :func:`guided_gt`).
1155        point: The new ``(row, col)`` click.
1156
1157    Returns:
1158        New :class:`Clicks` with the waypoint inserted.
1159    """
1160    p = np.asarray(point)
1161    best = None
1162    for name in ("trunk", "left", "right"):
1163        path = getattr(gt, name)
1164        if len(path):
1165            d = np.hypot(*(path - p).T)
1166            i = int(np.argmin(d))
1167            if best is None or d[i] < best[0]:

1171
1172    def pos(q: Point) -> int:

1174        return int(np.argmin(np.hypot(*(path - np.asarray(q)).T)))
1175

1177    # The trunk's first point (root) is fixed, so start after it.
1178    start = 1 if name == "trunk" else 0

1180    if name == "trunk":

1182    else:
