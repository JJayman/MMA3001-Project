treeskel.guided_gt

Click-guided main-branch ground truth from winter images.

The automatic method (treeskel.winter_gt) is kept as a baseline. It failed on many trees: posts, straight unbranched trees, gaps in depth, support wires, and branches that cross. Here a person supplies a few clicks per tree, and the branches are traced between them automatically:

  1. Clicks (Clicks): the trunk base, the fork, and the tip of each of the two V leaders, plus optional waypoints where a trace needs guiding.

  2. Cost map (branch_cost()): each pixel gets a "woodiness" in [0, 1] from three cues, and a cost floor + (1 - woodiness)^power:

    • depth: the pixel stands out from the ground or background (treeskel.winter_gt.foreground_mask(), smoothed), weighted by how central it is within the object (distance to the edge divided by the largest such distance nearby), so paths run down the middle of thick trunks rather than along an edge;
    • tube shape: the Frangi vesselness filter, which uses the eigenvalues of the image's Hessian (second derivatives) to respond to bright, elongated structures at the chosen widths;
    • colour: bark is pale and unsaturated, unlike grass and soil.

  3. Tracing (trace()): between consecutive clicks, the path with the smallest total cost is found by Dijkstra's algorithm over the 8-connected pixel grid (diagonal steps cost √2 × the pixel cost). Cheap woody pixels pull the path onto the branch, and short gaps are crossed where needed.

  4. Smoothing (smooth_segment()): the pixel path zig-zags by a pixel or two (bark texture, 8-connected steps), so each stretch between clicks is smoothed with the clicks held fixed.
  5. Widths: the trunk's width is measured from depth and fitted as a straight-line taper along its length by robust Huber regression (fit_taper(), huber_line()). Each leader's width is measured across the branch in the colour image (branch_edges()): every cross-section is split into background, branch and background by least squares, so both the sunlit and the shaded half of a branch lit from one side count. Depth is not used for leaders because it reaches about 2 px past each edge and merges with things behind. Each leader is drawn at its own robust width, widened near the fork by an amount shared by all leaders that fades with distance (fit_leader_radius()).
  6. Fork (end_cut(), fork_junction()): drawn as discs, the trunk would end in a half disc of its own radius, which shows as a round knob where the much thinner leaders leave it. So the trunk is cut flat at the fork (and at a root click that is well above the image's bottom edge), and each leader is joined to the trunk's edge on its outer side by a straight line a little way up the leader; the crotch between the leaders is left as the leaders draw it. The older shoulder_fill() (off by default since session 8) closed the notch beside each leader but kept the round top; it was needed while the leaders were drawn about half as wide as their bark.
  7. Result (guided_gt()): a treeskel.winter_gt.WinterGT, so the same rendering, shape measures and overlays apply to both methods.

Clicks are stored in a JSON file keyed by tree id (see save_clicks()), so the ground truth can be regenerated exactly with python -m treeskel.guided_gt DATA_DIR --clicks annotations/winter_clicks.json. Clicks are made with treeskel.annotate.

  96class GuidedParams:
  97    """Settings for the cost map and for drawing the branches.
  98
  99    The cost-map defaults were chosen by :mod:`treeskel.tune_cost` on 17 annotated
 100    trees (64 correction clicks). The first defaults (depth 0.5, tube 0.3,
 101    colour 0.2, power 2, centre weight 0.5) made wood almost free, so paths
 102    wandered within thick trunks and needed many corrections: 62% of the
 103    correction clicks lay more than 8 px from the trace made from the main
 104    clicks alone. The tuned setting keeps wood only moderately cheaper than
 105    background, so path length still matters, and fully favours the centre
 106    of each branch: 6% of correction clicks were more than 8 px off (11% in
 107    leave-one-out cross-validation). The colour cue got weight 0.
 108
 109    Attributes:
 110        depth_weight: Weight of the depth cue in woodiness.
 111        tube_weight: Weight of the Frangi tube cue.
 112        colour_weight: Weight of the pale-bark colour cue.
 113        sigmas: Frangi filter scales (Gaussian sigma, px), roughly half the
 114            branch widths to respond to.
 115        cost_floor: Smallest pixel cost; keeps paths from taking long detours
 116            through very woody areas.
 117        cost_power: Exponent on (1 − woodiness); higher values stick more
 118            tightly to woody pixels.
 119        centre_window: Half-size (px) of the neighbourhood used to judge how
 120            central a pixel is within its object; should exceed the widest
 121            trunk's half-width.
 122        centre_weight: How much the depth cue favours an object's centre line
 123            (0 = not at all, 1 = only the centre line counts fully).
 124        centre_source: ``"depth"`` to judge centredness on the depth
 125            foreground, or ``"wood"`` to judge it on the combined cues.
 126        wood_threshold: Woodiness above which a pixel counts as wood when
 127            ``centre_source="wood"``.
 128        smooth_sigma: Width (px) of the Gaussian that smooths each traced
 129            stretch between clicks (:func:`smooth_segment`); 0 = no smoothing.
 130            Not used by the cost map, so :mod:`treeskel.tune_cost` results
 131            are unaffected.
 132        leader_width_source: How leader widths are measured: ``"profile"``
 133            (default) finds both edges of the branch in colour cross-sections
 134            (:func:`branch_edges`); ``"scale_space"`` uses scale-space ridge
 135            detection (:func:`scale_space_radius`, the default until session
 136            8); ``"depth"`` uses the depth foreground like the trunk. On the
 137            21 development trees in the repository, ``"scale_space"`` gave
 138            about half the width of the bark: it responds to the sunlit half
 139            of a branch lit from one side. Depth reaches a median 2.0 px past
 140            clear bark edges; with that removed, it agrees with
 141            ``"profile"`` (median difference −0.4 px per leader), see
 142            :mod:`treeskel.measure_width`. Trunks always use depth.
 143        leader_scales: Range (px) of Gaussian scales searched for leaders
 144            (``"scale_space"`` only).
 145        scale_window: Half-size (px) of the neighbourhood searched around
 146            each path point, so a slightly off-centre path still finds the
 147            branch (``"scale_space"`` only).
 148        profile_half_width: How far (px) either side of the path each
 149            cross-section reaches (``"profile"`` only); wider than the widest
 150            leader plus a few pixels of background.
 151        profile_along: Cross-sections are averaged over this many path
 152            points either side (``"profile"`` only), which evens out bark
 153            texture and background clutter. Longer averages blurred the edges
 154            where leaders curve.
 155        leader_fit: ``"widening"`` (default) draws each leader at its own
 156            width, widened near the fork (:func:`fit_leader_radius`);
 157            ``"taper"`` fits a free straight taper per leader
 158            (:func:`fit_taper`, the method until session 8). Free tapers are
 159            unreliable: on the 21 development trees here, half of the leaders
 160            came out widening upwards (28% on all 449 development trees).
 161        fork_widening: How much wider a leader is at the fork than its own
 162            width further up (a fraction); 0 turns the widening off.
 163        widening_length: Distance (in trunk radii at the fork) over which
 164            the widening falls by a factor e. ``fork_widening`` and
 165            ``widening_length`` are shared by all leaders, and were chosen on
 166            all 449 development trees (:mod:`treeskel.measure_width`, grid up
 167            to 1.0 and 48 trunk radii): +35% at the fork fading over 12 trunk
 168            radii, so a leader narrows gradually along its length (+31% 1.5
 169            trunk radii from the fork, +15% at 10, +3% at 30). Leave-one-tree-
 170            out picked 0.30–0.35 and 12; the 5 row-grouped folds of
 171            ``splits.json`` picked 0.30–0.35 and 8–12, and on every fold the
 172            shape beat a constant width on held-out rows. (A first fit on 21
 173            trees, 17 of them the problem trees used for tuning, had chosen a
 174            length of 4.)
 175        leader_fit_start: A leader's own width is estimated from points at
 176            least this many trunk radii from the fork; nearer, the
 177            cross-section cuts through the top of the trunk. Cross-sections
 178            that could reach the other leader are not used either
 179            (:func:`clear_of`); on the development trees the first usable
 180            one is a median 2.1 trunk radii from the fork.
 181        shoulder_length: How far up each leader the shoulder fill reaches
 182            (:func:`shoulder_fill`), in multiples of the trunk's radius at
 183            the fork; 0 (the default) turns it off. Session 6 chose 1.4 with
 184            :mod:`treeskel.measure_fork`, when the leaders were drawn about
 185            half as wide as their bark and left a deep notch beside the
 186            trunk. With the leaders at their true width (session 8), the
 187            masks without any fill already cover the shoulder between the
 188            depth silhouette and the silhouette minus its measured 2 px
 189            overshoot, on all 449 development trees (0.914 against
 190            0.875–0.938 at 1.5 trunk radii), while 1.4 covered more than
 191            depth did. So the student turned it off, for the moment; 1.4
 192            restores the session-6 masks' fill (see
 193            ``docs/results/fork_shoulders/``). Not used by the cost map.
 194        junction_reach: How the trunk meets the leaders, in multiples of
 195            the trunk's radius at the fork; 0 keeps the round-ended trunk
 196            of the masks up to session 8. Drawn as discs, the trunk ended in
 197            a half disc of its own radius, and at the fork that round top
 198            showed between and beside the thinner leaders as a knob (the
 199            student's observation in session 8; the hand masks have none).
 200            The trunk is now cut flat at the fork (:func:`end_cut`), and on
 201            each leader's outer side the trunk's edge at the fork is joined
 202            by a straight line to the leader's edge this far up the leader
 203            (:func:`fork_junction`); the crotch between the leaders is left
 204            as the leaders draw it. 1.0 was chosen with
 205            :mod:`treeskel.measure_fork` on the 21 development trees in the
 206            repository, by the criterion that turned the shoulder fill off:
 207            the joins should cover the shoulder beside each leader about as
 208            much as the wood does, which lies between the raw depth
 209            silhouette and the silhouette minus its 2 px overshoot. The
 210            matching reach was 0.98 and 1.30 against the raw silhouette (for
 211            shoulders reaching 1.5 and 2 trunk radii up the leader) and 0.5
 212            or less against the shrunk one; 1.5 covered more than the raw
 213            silhouette at both. On all 449 development trees the matching
 214            reaches were 1.04 and 1.23 (raw) and 0.62 and 0.59 (shrunk), and
 215            1.0 lay between the two references at both
 216            (``docs/results/fork_junction/``). Not used by the cost map.
 217        flat_root: Cut the trunk flat at the root click too
 218            (:func:`end_cut`), where its round end would otherwise be drawn
 219            whole on the ground below the click: on trees whose root click
 220            is more than the trunk's radius above the image's bottom edge
 221            (about 1 in 10 development trees). Most root clicks are a few
 222            pixels above that edge (median 4 px), where the trunk leaves the
 223            frame; there the round end reaches the edge and is kept, since a
 224            flat cut would leave a strip of background under the trunk.
 225    """
 226
 227    depth_weight: float = 0.2
 228    tube_weight: float = 0.1
 229    colour_weight: float = 0.0
 230    sigmas: tuple[float, ...] = (2, 4, 6, 8, 10)
 231    cost_floor: float = 0.02
 232    cost_power: float = 1.0
 233    centre_window: int = 15
 234    centre_weight: float = 1.0
 235    centre_source: str = "depth"
 236    wood_threshold: float = 0.45
 237    smooth_sigma: float = 6.0
 238    leader_width_source: str = "profile"
 239    leader_scales: tuple[float, float] = (1.5, 12.0)
 240    scale_window: int = 4
 241    profile_half_width: int = 20
 242    profile_along: int = 3
 243    leader_fit: str = "widening"
 244    fork_widening: float = 0.35

 252@dataclass
 253class Clicks:
 254    """Clicked points for one tree, as ``(row, col)`` pixels.
 255
 256    Attributes:
 257        trunk: ``[root, waypoints..., fork]`` (at least two points).
 258        left: ``[waypoints..., tip]`` for the image-left leader; traced from
 259            the fork. If the tips were clicked in the other order,
 260            :meth:`normalised` swaps the leaders.
 261        right: ``[waypoints..., tip]`` for the image-right leader.
 262        skip: True if the tree cannot be annotated (it is then excluded).
 263        note: Free-text reason or comment.
 264    """
 265
 266    trunk: list[Point] = field(default_factory=list)
 267    left: list[Point] = field(default_factory=list)
 268    right: list[Point] = field(default_factory=list)
 269    skip: bool = False
 270    note: str = ""
 271
 272    @property
 273    def complete(self) -> bool:
 274        """True if there is enough to trace: root, fork and both tips."""
 275        return len(self.trunk) >= 2 and bool(self.left) and bool(self.right)
 276
 277    @property
 278    def fork(self) -> Point:
 279        """The fork (last trunk point)."""
 280        return self.trunk[-1]
 281
 282    def normalised(self) -> "Clicks":
 283        """Copy with the leaders swapped if the "left" tip is right of the other.
 284
 285        "Left" always means the leader whose tip is further left in the image,
 286        whatever order the tips were clicked in.
 287
 288        Returns:
 289            A new :class:`Clicks` with the leaders swapped, or these clicks if they are already in order.
 290        """
 291        if self.left and self.right and self.left[-1][1] > self.right[-1][1]:
 292            return Clicks(trunk=list(self.trunk), left=list(self.right), right=list(self.left),
 293                          skip=self.skip, note=self.note)
 294        return self
 295
 296    def to_json(self) -> dict:
 297        """Plain-data form for the JSON file.
 298
 299        Returns:
 300            ``{"trunk", "left", "right", "skip", "note"}`` with the points as lists.
 301        """
 302        d = asdict(self)
 303        for k in ("trunk", "left", "right"):
 304            d[k] = [list(map(int, p)) for p in d[k]]
 305        return d
 306
 307    @classmethod
 308    def from_json(cls, d: dict) -> "Clicks":
 309        """Inverse of :meth:`to_json`.
 310
 311        Args:
 312            d: A dict as written by :meth:`to_json` (missing keys default to empty).
 313
 314        Returns:
 315            The :class:`Clicks`.
 316        """
 317        return cls(
 318            trunk=[tuple(p) for p in d.get("trunk", [])],
 319            left=[tuple(p) for p in d.get("left", [])],
 320            right=[tuple(p) for p in d.get("right", [])],
 321            skip=bool(d.get("skip", False)),
 322            note=str(d.get("note", "")),
 323        )

 341def save_clicks(path: str | Path, clicks: dict[str, Clicks]) -> None:
 342    """Write a clicks file atomically (a crash never leaves it half-written).
 343
 344    Args:
 345        path: The JSON file to write.
 346        clicks: The clicks per tree id.
 347    """
 348    path = Path(path)
 349    path.parent.mkdir(parents=True, exist_ok=True)
 350    data = {k: clicks[k].to_json() for k in sorted(clicks)}
 351    fd, tmp = tempfile.mkstemp(dir=path.parent, suffix=".tmp")
 352    with os.fdopen(fd, "w") as f:
 353        json.dump(data, f, indent=1)
 354    os.replace(tmp, path)

 357def _centredness(mask: np.ndarray, window: int) -> np.ndarray:
 358    """Distance to the mask edge divided by the largest such distance nearby.
 359
 360    1 on an object's centre line, falling towards 0 at its edges, whatever the
 361    object's width (up to ``window`` px half-width).
 362    """
 363    edt = ndi.distance_transform_edt(mask)
 364    local_max = ndi.maximum_filter(edt, size=2 * window + 1)
 365    return np.divide(edt, local_max, out=np.zeros_like(edt), where=local_max > 0)

 368def cost_cues(rgb: np.ndarray, depth: np.ndarray, valid: np.ndarray,
 369              params: GuidedParams = GuidedParams()) -> dict[str, np.ndarray]:
 370    """The expensive, weight-independent parts of the cost map.
 371
 372    Computed once per image so that many weightings can be tried cheaply
 373    (see :func:`combine_cues` and :mod:`treeskel.tune_cost`).
 374
 375    Args:
 376        rgb: The winter ``(480, 640, 3)`` uint8 photo.
 377        depth: Its ``(480, 640)`` uint8 depth.
 378        valid: Boolean mask of the depth's readings.
 379        params: Uses ``sigmas`` and ``centre_window``.
 380
 381    Returns:
 382        Dict of ``(H, W)`` float arrays in [0, 1]: ``"fg"`` (smoothed depth
 383        foreground), ``"fg_centred"`` (its centredness), ``"tube"`` (Frangi
 384        response) and ``"pale"`` (bark colour).
 385    """
 386    mask = foreground_mask(depth, valid)
 387    grey = rgb.astype(float).mean(2) / 255.0
 388    tube = frangi(grey, sigmas=params.sigmas, black_ridges=False)
 389    scale = np.percentile(tube, 99.5)
 390    tube = np.clip(tube / scale, 0, 1) if scale > 0 else np.zeros_like(tube)
 391    hsv = rgb2hsv(rgb)
 392    pale = np.clip((hsv[..., 2] - 0.35) / 0.5, 0, 1) * np.clip(1 - hsv[..., 1] / 0.45, 0, 1)
 393    return {
 394        "fg": ndi.gaussian_filter(mask.astype(float), 1.0),
 395        "fg_centred": _centredness(mask, params.centre_window),
 396        "tube": tube,
 397        "pale": pale,
 398    }

 401def combine_cues(cues: dict[str, np.ndarray],
 402                 params: GuidedParams = GuidedParams()) -> tuple[np.ndarray, np.ndarray]:
 403    """Weight the cues into woodiness and cost.
 404
 405    ``woodiness = w_depth · fg · (1 − c + c · centred) + w_tube · tube +
 406    w_colour · pale`` (clipped to [0, 1]), where ``c`` is ``centre_weight``.
 407    ``centred`` is the centredness of the depth foreground
 408    (``centre_source="depth"``) or of the pixels whose woodiness without
 409    centring exceeds ``wood_threshold`` (``centre_source="wood"``). The
 410    latter uses colour and shape too, so ground pixels that merge into the
 411    trunk base in depth do not pull the centre line sideways.
 412
 413    Args:
 414        cues: The cues from :func:`cost_cues`.
 415        params: The weights and the centring settings.
 416
 417    Returns:
 418        ``(cost, woodiness)``; cost is ``cost_floor + (1 − woodiness)^cost_power``.
 419    """
 420    p = params
 421    base = p.tube_weight * cues["tube"] + p.colour_weight * cues["pale"]
 422    if p.centre_source == "wood":
 423        rough = np.clip(p.depth_weight * cues["fg"] + base, 0, 1)
 424        centred = _centredness(rough > p.wood_threshold, p.centre_window)
 425    else:
 426        centred = cues["fg_centred"]
 427    depth_term = cues["fg"] * (1 - p.centre_weight + p.centre_weight * centred)
 428    wood = np.clip(p.depth_weight * depth_term + base, 0, 1)
 429    return p.cost_floor + (1 - wood) ** p.cost_power, wood

 449def smooth_segment(seg: np.ndarray, sigma: float) -> np.ndarray:
 450    """Smooth a traced segment while keeping both end points exactly fixed.
 451
 452    The segment is split into the straight line between its end points plus
 453    a residual (the path's sideways wiggle). Only the residual is smoothed,
 454    with a Gaussian of width ``sigma`` (in path steps, about pixels), after
 455    an odd reflection at each end, which keeps the residual zero there. Real
 456    bends are kept, pixel-scale zig-zags are removed, and the result is
 457    re-drawn as a connected 8-connected pixel path.
 458
 459    Args:
 460        seg: ``(M, 2)`` connected path from one click to the next.
 461        sigma: Smoothing width; 0 returns ``seg`` unchanged.
 462
 463    Returns:
 464        ``(K, 2)`` int connected path with the same first and last points.
 465    """
 466    if sigma <= 0 or len(seg) < 5:
 467        return seg
 468    p = seg.astype(float)
 469    step = np.hypot(*np.diff(p, axis=0).T)
 470    t = np.concatenate([[0.0], np.cumsum(step)])
 471    t /= t[-1] if t[-1] > 0 else 1.0
 472    line = p[0] + t[:, None] * (p[-1] - p[0])
 473    res = p - line                                      # zero at both ends
 474    k = min(len(res) - 1, int(4 * sigma) + 1)
 475    ext = np.concatenate([-res[k:0:-1], res, -res[-2:-k - 2:-1]])  # odd reflection
 476    sm = ndi.gaussian_filter1d(ext, sigma, axis=0, mode="nearest")[k:k + len(res)]
 477    sm[0] = sm[-1] = 0.0
 478    pts = np.round(line + sm).astype(int)
 479    out = [tuple(pts[0])]
 480    for a, b in zip(pts[:-1], pts[1:]):
 481        if tuple(b) != out[-1]:
 482            rr, cc = draw_line(out[-1][0], out[-1][1], int(b[0]), int(b[1]))
 483            out.extend(zip(rr[1:].tolist(), cc[1:].tolist()))
 484    return np.array(out, int)

 487def trace(cost: np.ndarray, points: Sequence[Point], smooth_sigma: float = 0.0) -> np.ndarray:
 488    """Cheapest 8-connected path through ``points`` in order.
 489
 490    Args:
 491        cost: ``(H, W)`` positive cost map.
 492        points: Two or more ``(row, col)`` points.
 493        smooth_sigma: If > 0, each stretch between consecutive points is
 494            smoothed by :func:`smooth_segment`; the points themselves stay on
 495            the path.
 496
 497    Returns:
 498        ``(N, 2)`` int array of path pixels from the first to the last point,
 499        passing through every point.
 500    """
 501    h, w = cost.shape
 502    pts = [(min(max(int(r), 0), h - 1), min(max(int(c), 0), w - 1)) for r, c in points]
 503    out: list[tuple[int, int]] = [pts[0]]
 504    for a, b in zip(pts[:-1], pts[1:]):
 505        if a == b:
 506            continue
 507        seg, _ = route_through_array(cost, a, b, fully_connected=True, geometric=True)
 508        seg = smooth_segment(np.array(seg, int), smooth_sigma)
 509        seg[:, 0] = seg[:, 0].clip(0, h - 1)
 510        seg[:, 1] = seg[:, 1].clip(0, w - 1)
 511        out.extend(tuple(q) for q in seg[1:].tolist())
 512    return np.array(out, int).reshape(-1, 2)

 515def guided_gt(rgb: np.ndarray, depth: np.ndarray, valid: np.ndarray, clicks: Clicks,
 516              params: GuidedParams = GuidedParams(), cost: np.ndarray | None = None) -> WinterGT:
 517    """Trace the trunk and both leaders through the clicked points.
 518
 519    Args:
 520        rgb: The tree's winter ``(480, 640, 3)`` uint8 photo.
 521        depth: Its ``(480, 640)`` uint8 depth.
 522        valid: Boolean mask of the depth's readings.
 523        clicks: Complete :class:`Clicks` (not skipped).
 524        params: Settings; the cost-map ones are ignored if ``cost`` is given.
 525        cost: Precomputed cost map, to avoid recomputing it while clicking.
 526
 527    Returns:
 528        A :class:`treeskel.winter_gt.WinterGT` with ``ok=True``. Its
 529        ``tree_mask`` is the depth foreground, used for branch widths.
 530
 531    Raises:
 532        ValueError: If the clicks are skipped or incomplete.
 533    """
 534    if clicks.skip or not clicks.complete:
 535        raise ValueError("clicks must be complete and not skipped")
 536    clicks = clicks.normalised()
 537    if cost is None:
 538        cost, _ = branch_cost(rgb, depth, valid, params)
 539    fg = ndi.binary_closing(foreground_mask(depth, valid), disk(2))
 540    sm = params.smooth_sigma
 541    trunk = trace(cost, clicks.trunk, sm)
 542    left = trace(cost, [clicks.fork, *clicks.left], sm)
 543    right = trace(cost, [clicks.fork, *clicks.right], sm)
 544    radius = ndi.distance_transform_edt(fg)
 545    skel = np.zeros(fg.shape, bool)
 546    for p in (trunk, left, right):
 547        skel[p[:, 0], p[:, 1]] = True
 548    measured = {k: radius[p[:, 0], p[:, 1]] for k, p in (("trunk", trunk), ("left", left), ("right", right))}
 549    if params.leader_width_source == "profile":
 550        for k, p, other in (("left", left, right), ("right", right, left)):
 551            first, last = branch_edges(rgb, p, params.profile_half_width, params.profile_along)
 552            widths = (last - first + 1) / 2.0
 553            # Near the fork a cross-section can reach the other leader and take it in too.
 554            widths[~clear_of(p, other, params.profile_half_width + NEIGHBOUR_MARGIN)] = np.nan
 555            measured[k] = widths
 556    elif params.leader_width_source == "scale_space":
 557        grey = rgb.astype(float).mean(2) / 255.0
 558        both = np.concatenate([left, right])
 559        r = scale_space_radius(grey, both, params.leader_scales, params.scale_window)
 560        measured["left"], measured["right"] = r[:len(left)], r[len(left):]
 561    elif params.leader_width_source != "depth":
 562        raise ValueError(f"unknown leader_width_source {params.leader_width_source!r}")
 563    radii = {"trunk": fit_taper(trunk, measured["trunk"], "trunk")}
 564    fork_r = _fork_radius(radii)
 565    for k, p in (("left", left), ("right", right)):
 566        if params.leader_fit == "widening":
 567            radii[k] = fit_leader_radius(p, measured[k], fork_r, params.fork_widening, params.widening_length,
 568                                         params.leader_fit_start, part=k)
 569        elif params.leader_fit == "taper":
 570            radii[k] = fit_taper(p, measured[k], k)
 571        else:
 572            raise ValueError(f"unknown leader_fit {params.leader_fit!r}")
 573        # A leader cannot start wider than the trunk it grows from.
 574        radii[k] = np.minimum(radii[k], fork_r)
 575    gt = WinterGT(
 576        tree_mask=fg, skeleton=skel, radii=radii,
 577        root=tuple(map(int, trunk[0])), fork=tuple(map(int, trunk[-1])),
 578        trunk=trunk, left=left, right=right,
 579        trunk_shape=path_shape(trunk, radius), left_shape=path_shape(left, radius),
 580        right_shape=path_shape(right, radius), ok=True,
 581    )
 582    # Fill the notches between the trunk and each leader's outer side (none if shoulder_length is 0).
 583    gt.shoulders = fill_shoulders(gt, params.shoulder_length)
 584    cuts = []
 585    if params.junction_reach > 0:
 586        # Square the trunk's top off, and join it to each leader with straight sides.
 587        cuts.append(end_cut(trunk, radii["trunk"][-1]))
 588        gt.junction = fork_junction(gt, params.junction_reach)
 589    if params.flat_root and trunk[0, 0] + radii["trunk"][0] < fg.shape[0] - 1:
 590        # The round end would lie wholly in the image, on the ground below the click. (Nearer the
 591        # bottom edge, the trunk leaves the frame, and the round end reaches the edge: kept.)
 592        cuts.append(end_cut(trunk[::-1], radii["trunk"][0]))
 593    gt.trunk_cuts = [c for c in cuts if c is not None] or None
 594    return gt

 608def clear_of(path: np.ndarray, other: np.ndarray, distance: float) -> np.ndarray:
 609    """True for the points of ``path`` further than ``distance`` px from every point of ``other``.
 610
 611    Used to drop cross-sections that could include the other leader: near
 612    the fork the two leaders are close together, and a cross-section across
 613    one then takes in the other as well. On a synthetic tree with leaders of
 614    constant width, such cross-sections measured the leaders 1.7–2.4 times too
 615    wide up to 3 trunk radii from the fork.
 616
 617    Args:
 618        path: ``(N, 2)`` points.
 619        other: ``(M, 2)`` points of the other branch.
 620        distance: Clearance (px).
 621
 622    Returns:
 623        ``(N,)`` boolean; all True if ``other`` is empty.
 624    """
 625    if len(path) == 0 or len(other) == 0:
 626        return np.ones(len(path), bool)
 627    return cKDTree(other).query(path)[0] > distance

 630def huber_line(x: np.ndarray, y: np.ndarray, k: float = 1.345, iters: int = 30) -> tuple[float, float]:
 631    """Robust straight-line fit ``y ≈ a + b·x`` by Huber regression.
 632
 633    Iteratively reweighted least squares: residuals within ``k`` robust
 634    standard deviations (scale = 1.4826 × median absolute residual) get full
 635    weight, larger ones weight ``k·σ/|r|``, so outliers pull the line far less
 636    than in ordinary least squares.
 637
 638    Args:
 639        x: Positions.
 640        y: Values, one per position.
 641        k: Huber's tuning constant (in robust SDs).
 642        iters: Most reweighting rounds.
 643
 644    Returns:
 645        ``(a, b)``; ``b = 0`` if ``x`` has no spread.
 646    """
 647    x, y = np.asarray(x, float), np.asarray(y, float)
 648    if np.ptp(x) == 0:
 649        return float(np.median(y)), 0.0
 650    X = np.stack([np.ones_like(x), x], 1)
 651    w = np.ones_like(y)
 652    beta = np.zeros(2)
 653    for _ in range(iters):
 654        sw = np.sqrt(w)
 655        new, *_ = np.linalg.lstsq(X * sw[:, None], y * sw, rcond=None)
 656        res = y - X @ new
 657        scale = 1.4826 * np.median(np.abs(res)) or 1e-9
 658        u = np.abs(res) / (k * scale)
 659        w = np.where(u <= 1, 1.0, 1.0 / np.maximum(u, 1e-12))
 660        if np.allclose(new, beta, atol=1e-6):
 661            break
 662        beta = new
 663    return float(new[0]), float(new[1])

 666def huber_location(y: np.ndarray, k: float = 1.345, iters: int = 30) -> float:
 667    """Robust average of ``y`` by Huber's M-estimator (see :func:`huber_line`).
 668
 669    Starts from the median; values more than ``k`` robust standard
 670    deviations away are down-weighted, so a minority of outliers (e.g.
 671    cross-sections that also caught a branch behind) barely move it.
 672
 673    Args:
 674        y: Values.
 675        k: Huber's tuning constant (in robust SDs).
 676        iters: Most reweighting rounds.
 677
 678    Returns:
 679        The robust average (the last estimate if ``iters`` rounds do not settle it).
 680    """
 681    y = np.asarray(y, float)
 682    m = float(np.median(y))
 683    for _ in range(iters):
 684        res = y - m
 685        scale = 1.4826 * np.median(np.abs(res)) or 1e-9
 686        u = np.abs(res) / (k * scale)
 687        w = np.where(u <= 1, 1.0, 1.0 / np.maximum(u, 1e-12))
 688        new = float(np.sum(w * y) / np.sum(w))
 689        if abs(new - m) < 1e-6:
 690            return new
 691        m = new
 692    return m

 695def scale_space_radius(grey: np.ndarray, points: np.ndarray, scales: tuple[float, float] = (1.5, 12.0),
 696                       window: int = 4, ratio: float = 1.2) -> np.ndarray:
 697    """Branch half-width at each point, by scale-space ridge detection.
 698
 699    The image is smoothed with Gaussians of width σ over a geometric range of
 700    scales. At each scale the larger-magnitude eigenvalue of the Hessian
 701    (curvature across a branch), multiplied by σ² (scale normalisation), is
 702    computed; its sign is ignored, so bark lighter than grass and bark
 703    darker than sky both count. For a bar of half-width *a* this normalised
 704    response peaks at σ = *a* (the maximum of 2u·φ(u) is at u = a/σ = 1), so
 705    the scale of the strongest response within ``window`` px of each point
 706    is taken as its half-width. On synthetic bars that are brighter than the
 707    background right to their edges, of half-width 3–12 px, the error is at
 708    most 0.5 px.
 709
 710    Real bark is not like that: a branch lit from one side is bright on that
 711    side and dark on the other, and its edges are darker than its middle.
 712    On such (Lambertian) bars this returns about 0.55–0.6 of the half-width,
 713    and on the development trees about half the bark's width, so it is no
 714    longer the default (see :func:`branch_edges`).
 715
 716    Only a box around the points (padded by 3σ) is filtered, to save time.
 717
 718    Args:
 719        grey: ``(H, W)`` float image.
 720        points: ``(N, 2)`` ``(row, col)`` points.
 721        scales: Smallest and largest σ searched (px).
 722        window: Search half-size around each point (px).
 723        ratio: Ratio between successive scales.
 724
 725    Returns:
 726        ``(N,)`` half-widths (px).
 727    """
 728    if len(points) == 0:
 729        return np.zeros(0)
 730    sig = scales[0] * ratio ** np.arange(int(np.log(scales[1] / scales[0]) / np.log(ratio)) + 1)
 731    pad = int(3 * sig[-1]) + window + 1
 732    r0, c0 = np.maximum(points.min(0) - pad, 0)
 733    r1, c1 = np.minimum(points.max(0) + pad + 1, grey.shape)
 734    crop = grey[r0:r1, c0:c1].astype(float)
 735    best_resp = np.full(len(points), -np.inf)
 736    best_sig = np.full(len(points), sig[0])
 737    pr, pc = points[:, 0] - r0, points[:, 1] - c0
 738    for s in sig:
 739        h = hessian_matrix(crop, sigma=s, order="rc", use_gaussian_derivatives=True)
 740        ev = hessian_matrix_eigvals(h)
 741        resp = ndi.maximum_filter(s * s * np.maximum(np.abs(ev[0]), np.abs(ev[1])), size=2 * window + 1)
 742        v = resp[pr, pc]
 743        better = v > best_resp
 744        best_resp[better], best_sig[better] = v[better], s
 745    return best_sig

 748def path_normals(path: np.ndarray, half: int = 6) -> np.ndarray:
 749    """Unit normals to a path, from the chord ``half`` points either side.
 750
 751    The chord ignores pixel-scale wiggles. The normal is the direction of
 752    travel turned by 90° to its left, ``(−d_col, d_row)``.
 753
 754    Args:
 755        path: ``(N, 2)`` ``(row, col)`` points in order.
 756        half: Chord half-length in points (shortened at the ends).
 757
 758    Returns:
 759        ``(N, 2)`` unit vectors ``(d_row, d_col)``; zero where the path does
 760        not move.
 761    """
 762    n = len(path)
 763    i = np.arange(n)
 764    d = (path[np.minimum(i + half, n - 1)] - path[np.maximum(i - half, 0)]).astype(float)
 765    size = np.hypot(d[:, 0], d[:, 1])[:, None]
 766    d = np.divide(d, size, out=np.zeros_like(d), where=size > 0)
 767    return np.stack([-d[:, 1], d[:, 0]], 1)

 770def straighten(image: np.ndarray, path: np.ndarray, half_width: int, order: int = 1) -> np.ndarray:
 771    """Sample an image across a path: one row per path point.
 772
 773    Row ``i`` holds the image along the normal at point ``i``
 774    (:func:`path_normals`), from ``−half_width`` to ``+half_width`` px, so
 775    the branch runs down the middle column. Samples outside the image take
 776    the nearest edge value.
 777
 778    Args:
 779        image: ``(H, W)`` or ``(H, W, C)`` array.
 780        path: ``(N, 2)`` ``(row, col)`` points.
 781        half_width: Reach either side of the path (px).
 782        order: Interpolation order (1 = bilinear, 0 = nearest).
 783
 784    Returns:
 785        ``(N, 2·half_width + 1)`` or ``(N, 2·half_width + 1, C)`` float array.
 786    """
 787    normals = path_normals(path)
 788    off = np.arange(-half_width, half_width + 1)[None, :]
 789    coords = [path[:, :1] + off * normals[:, :1], path[:, 1:] + off * normals[:, 1:]]
 790    img = np.asarray(image, float)
 791    if img.ndim == 2:
 792        return ndi.map_coordinates(img, coords, order=order, mode="nearest")
 793    return np.stack([ndi.map_coordinates(img[..., k], coords, order=order, mode="nearest")
 794                     for k in range(img.shape[2])], -1)

 797def _cumsum0(values: np.ndarray, axis: int) -> np.ndarray:
 798    """Cumulative sum along ``axis`` with a leading zero (so sums over i0..i1-1 are c[i1] − c[i0])."""
 799    pad = [(0, 0)] * values.ndim
 800    pad[axis] = (1, 0)
 801    return np.cumsum(np.pad(values, pad), axis=axis)

 804def profile_edges(profiles: np.ndarray, min_background: int = 3, min_half: int = 1) -> tuple[np.ndarray, np.ndarray]:
 805    """Where the branch starts and ends in each cross-section profile.
 806
 807    Each profile is modelled in three pieces and fitted by least squares:
 808    the background on one side (a constant colour), the branch (a quadratic
 809    in position, per colour channel) and the background on the other side
 810    (a constant). A branch lit from one side is bright on that side and dark
 811    on the other; the quadratic follows that shading across the whole branch,
 812    whereas an edge or ridge detector stops at the change from the lit to
 813    the shaded half. Every pair of change points is tried: the squared
 814    error of each piece comes from cumulative sums of the samples and their
 815    powers, so all pairs are scored at once. The branch must include the
 816    centre (the path).
 817
 818    On synthetic branches lit from the front or either side, of half-width
 819    3–9 px with the path up to 2 px off-centre, the half-width was found to
 820    within 0.5 px in 47 of 48 cases, and within 1 px in the last (a
 821    front-lit branch whose dark rim was as bright as the background).
 822    Where a shaded half is as dark as the background next to it, it can be
 823    left out; the robust fit along the leader (:func:`fit_leader_radius`)
 824    absorbs such points.
 825
 826    Args:
 827        profiles: ``(M, N)`` or ``(M, N, C)`` samples across the branch, ``N``
 828            odd, centred on the path (e.g. from :func:`straighten`).
 829        min_background: Fewest background samples on each side.
 830        min_half: The branch reaches at least this many samples either side
 831            of the centre.
 832
 833    Returns:
 834        ``(first, last)``: ``(M,)`` int offsets from the centre (px) of the
 835        first and last branch samples. The half-width is
 836        ``(last − first + 1) / 2``.
 837
 838    Raises:
 839        ValueError: If the profiles are too short for ``min_background`` background and ``min_half`` branch
 840            samples on each side.
 841    """
 842    p = np.asarray(profiles, float)
 843    if p.ndim == 2:
 844        p = p[..., None]
 845    m, n, _ = p.shape
 846    half = n // 2
 847    if m == 0:
 848        return np.zeros(0, int), np.zeros(0, int)
 849    x = (np.arange(n) - half) / max(half, 1)                       # in [-1, 1], for conditioning
 850    firsts = np.arange(min_background, half - min_half + 1)
 851    lasts = np.arange(half + min_half, n - min_background)
 852    if len(firsts) == 0 or len(lasts) == 0:
 853        raise ValueError(f"profiles of {n} samples are too short for {min_background} background "
 854                         f"and {min_half} branch samples on each side")
 855    a, b = (g.ravel() for g in np.meshgrid(firsts, lasts, indexing="ij"))
 856    sx = _cumsum0(np.stack([x ** k for k in range(5)]), 1)          # (5, n+1): sums of x^k
 857    sxy = _cumsum0(np.stack([x ** k for k in range(3)])[:, None, :, None] * p[None], 2)  # (3, m, n+1, C)
 858    syy = _cumsum0((p ** 2).sum(-1), 1)                            # (m, n+1)
 859
 860    def constant_sse(i0: np.ndarray, i1: np.ndarray) -> np.ndarray:
 861        """Squared error of the best constant over samples i0..i1-1, per profile and pair."""
 862        s = sxy[0][:, i1] - sxy[0][:, i0]
 863        return syy[:, i1] - syy[:, i0] - (s ** 2).sum(-1) / (i1 - i0)
 864
 865    # Quadratic over a..b: normal equations G β = r, error = Σy² − rᵀG⁻¹r.
 866    i0, i1 = a, b + 1
 867    gram = np.stack([np.stack([sx[j + k][i1] - sx[j + k][i0] for k in range(3)], -1) for j in range(3)], -2)
 868    r = np.stack([sxy[j][:, i1] - sxy[j][:, i0] for j in range(3)], 2)   # (m, pairs, 3, C)
 869    solved = np.einsum("pjk,mpkc->mpjc", np.linalg.inv(gram), r)
 870    quadratic = syy[:, i1] - syy[:, i0] - (r * solved).sum((2, 3))
 871    cost = constant_sse(np.zeros_like(a), a) + quadratic + constant_sse(b + 1, np.full_like(b, n))
 872    best = np.argmin(cost, 1)
 873    return a[best] - half, b[best] - half
 874

 876def branch_edges(rgb: np.ndarray, path: np.ndarray, half_width: int = 20,
 877                 along: int = 3) -> tuple[np.ndarray, np.ndarray]:
 878    """Both edges of a branch at each point of its path, from the colour image.
 879
 880    The image is sampled across the path (:func:`straighten`), each
 881    cross-section is averaged with its ``along`` neighbours either side, and
 882    the edges are found by :func:`profile_edges`.
 883
 884    Args:
 885        rgb: ``(H, W, 3)`` colour image.
 886        path: ``(N, 2)`` points along the branch.
 887        half_width: Reach of each cross-section either side of the path (px).
 888        along: Cross-sections averaged either side of each point.
 889
 890    Returns:
 891        ``(first, last)``: ``(N,)`` int offsets (px) of the branch's edges
 892        along each point's normal (:func:`path_normals`).
 893    """
 894    if len(path) == 0:
 895        return np.zeros(0, int), np.zeros(0, int)
 896    samples = straighten(rgb, path, half_width)
 897    if along > 0:
 898        samples = ndi.uniform_filter1d(samples, 2 * along + 1, axis=0, mode="nearest")
 899    return profile_edges(samples)

 902def fit_leader_radius(path: np.ndarray, measured: np.ndarray, fork_radius: float, widening: float = 0.35,
 903                      length: float = 12.0, start: float = 1.5, part: str = "left",
 904                      min_valid: float = 2.5, min_points: int = 8) -> np.ndarray:
 905    """A leader's drawing radius: its own width, widened near the fork.
 906
 907    ``r(s) = c · (1 + widening · exp(−s / (length · R)))``, where ``s`` is the
 908    distance along the leader from the fork and ``R`` the trunk's radius at
 909    the fork. The shape is shared by all leaders (see
 910    :attr:`GuidedParams.fork_widening`), because one leader's widths are
 911    too noisy to fit its own taper: with a free straight taper, half of
 912    the development trees' leaders came out widening upwards. Only the
 913    leader's own width ``c`` is fitted, as a robust (Huber) average of
 914    ``measured / (1 + widening · exp(…))`` over the points at least
 915    ``start · R`` from the fork. Nearer, the cross-section cuts through the
 916    top of the trunk. Measurements at or below ``min_valid`` (failed edges)
 917    or nan (no measurement, e.g. a cross-section that could include the
 918    other leader, see :func:`clear_of`) are ignored. With fewer than
 919    ``min_points`` usable measurements,
 920    :data:`FALLBACK_RADIUS` is used for ``c``. The result is clipped to
 921    :data:`RADIUS_LIMITS`.
 922
 923    Args:
 924        path: ``(N, 2)`` leader path starting at the fork.
 925        measured: ``(N,)`` measured half-widths (px), nan where not measured.
 926        fork_radius: The trunk's radius at the fork, ``R`` (px).
 927        widening: Extra width at the fork, as a fraction of ``c``.
 928        length: Distance over which the widening falls by a factor e, in
 929            trunk radii.
 930        start: Nearest distance from the fork used to fit ``c``, in trunk
 931            radii.
 932        part: ``"left"`` or ``"right"`` (for the limits and fallback).
 933        min_valid: Measurements at or below this (px) are failed edges, not used.
 934        min_points: Fewest usable measurements for a fit; with fewer, the fallback radius.
 935
 936    Returns:
 937        ``(N,)`` radii to draw.
 938    """
 939    lo, hi = RADIUS_LIMITS[part]
 940    if len(path) == 0:
 941        return np.zeros(0)
 942    s = arc_length(path)
 943    shape = 1 + widening * np.exp(-s / max(length * fork_radius, 1e-9))
 944    use = (measured > min_valid) & (s >= start * fork_radius)
 945    level = huber_location(measured[use] / shape[use]) if use.sum() >= min_points else FALLBACK_RADIUS[part]
 946    return np.clip(level * shape, lo, hi)

 949def fit_taper(path: np.ndarray, measured: np.ndarray, part: str,
 950              min_valid: float = 2.5, min_points: int = 8) -> np.ndarray:
 951    """Smooth, tapering radius along one part from noisy width measurements.
 952
 953    Width measured from depth is unreliable point by point: depth gaps give
 954    near-zero widths (drawn as thin lines), and ground or background merging
 955    with the branch gives large blobs. Treating the measurements as noisy
 956    observations, radius is modelled as linear in arc length along the path
 957    (a branch tapers gradually) and fitted by :func:`huber_line`, ignoring
 958    measurements at or below ``min_valid`` (gaps). A fit that widens upwards
 959    is physically implausible, so it is replaced by the median width
 960    (constant). The result is clipped to
 961    :data:`RADIUS_LIMITS`. With fewer than ``min_points`` usable
 962    measurements, :data:`FALLBACK_RADIUS` is used.
 963
 964    Args:
 965        path: ``(N, 2)`` path points, in order.
 966        measured: ``(N,)`` measured half-widths at those points (px).
 967        part: ``"trunk"``, ``"left"`` or ``"right"``.
 968        min_valid: Measurements at or below this (px) are gaps, not used.
 969        min_points: Fewest usable measurements for a fit; with fewer, the fallback radius.
 970
 971    Returns:
 972        ``(N,)`` radii to draw.
 973    """
 974    lo, hi = RADIUS_LIMITS[part]
 975    if len(path) == 0:
 976        return np.zeros(0)
 977    s = arc_length(path)
 978    ok = measured > min_valid
 979    if ok.sum() < min_points:
 980        return np.full(len(path), FALLBACK_RADIUS[part])
 981    a, b = huber_line(s[ok], measured[ok])
 982    if b > 0:
 983        # Branches do not widen upwards: use a constant (robust) width instead.
 984        a, b = float(np.median(measured[ok])), 0.0
 985    return np.clip(a + b * s, lo, hi)

 988def arc_length(path: np.ndarray) -> np.ndarray:
 989    """Distance (px) along ``path`` from its first point to each point.
 990
 991    Args:
 992        path: ``(N, 2)`` points, in order.
 993
 994    Returns:
 995        ``(N,)`` distances (px); zeros for fewer than 2 points.
 996    """
 997    if len(path) < 2:
 998        return np.zeros(len(path))
 999    return np.concatenate([[0.0], np.cumsum(np.hypot(*np.diff(path, axis=0).T))])

1002def outward_normal(path: np.ndarray, other: np.ndarray, reach: float) -> np.ndarray:
1003    """Unit normal to a leader's direction near the fork, on its outer side.
1004
1005    The direction is the chord from the fork to the point ``reach`` px along
1006    the path, which ignores pixel-scale wiggles. Of its two normals, the one
1007    pointing from the other leader (at the same distance along it) towards
1008    this one is returned, i.e. away from the crotch between the leaders.
1009
1010    Args:
1011        path: ``(N, 2)`` leader path starting at the fork.
1012        other: ``(M, 2)`` the other leader's path, also starting at the fork.
1013        reach: Chord length (px).
1014
1015    Returns:
1016        ``(2,)`` unit vector ``(d_row, d_col)``, or zeros if the path does
1017        not move away from the fork.
1018    """
1019    i = min(int(np.searchsorted(arc_length(path), reach)), len(path) - 1)
1020    j = min(int(np.searchsorted(arc_length(other), reach)), len(other) - 1)
1021    d = (path[i] - path[0]).astype(float)
1022    n = np.array([-d[1], d[0]])
1023    if n @ (path[i] - other[j]) < 0:
1024        n = -n
1025    size = np.hypot(*n)
1026    return n / size if size > 0 else np.zeros(2)

1029def shoulder_fill(shape: tuple[int, int], leader: np.ndarray, other: np.ndarray, radii: np.ndarray,
1030                  fork_radius: float, length: float) -> np.ndarray:
1031    """Pixels that fill the notch ("shoulder") beside a leader where it leaves the trunk.
1032
1033    Each leader's radius is one taper fitted along its whole length
1034    (:func:`fit_taper`), so a thin leader starts abruptly out of the round
1035    end of a much wider trunk, leaving a notch on its outer side. In the
1036    winter depth images the wood fills that notch: the trunk's edge runs
1037    into the leader's outer edge. So on the leader's outer side
1038    (:func:`outward_normal`), the mask is filled out to the convex hull of
1039    the trunk's end (its disc of radius ``R`` at the fork) and the leader's
1040    first ``length`` px. Its edge is the straight line from the trunk's edge
1041    to the leader's edge ``length`` px up the leader.
1042
1043    The fill never reaches outside that hull, so it cannot widen a straight
1044    trunk, and the crotch (between the leaders) is left as drawn. Other
1045    shapes were tried on the development trees and rejected (see
1046    ``docs/results/fork_shoulders/``). For example, widening both sides of
1047    each leader also filled the crotch, where many of the added pixels were
1048    not wood in depth; and widening the leader's discs smoothly into the
1049    trunk (a flare) bulged past the trunk's straight edges on a synthetic
1050    tree of known shape.
1051
1052    Args:
1053        shape: Image shape ``(H, W)``.
1054        leader: ``(N, 2)`` leader path starting at the fork.
1055        other: ``(M, 2)`` the other leader's path, to tell the outer side.
1056        radii: ``(N,)`` the leader's drawing radii (px).
1057        fork_radius: The trunk's drawing radius at the fork, ``R`` (px).
1058        length: How far along the leader the fill reaches (px); 0 or less
1059            gives an empty mask.
1060
1061    Returns:
1062        ``(H, W)`` bool mask of the fill, to be added to the drawn branches.
1063    """
1064    out = np.zeros(shape, bool)
1065    if length <= 0 or len(leader) == 0:
1066        return out
1067    base = leader[arc_length(leader) <= length]       # a prefix: arc length only grows
1068    fork = leader[0]
1069    # Work in a box around the fork that holds every disc (and so their hull).
1070    pad = int(np.ceil(max(fork_radius, radii[:len(base)].max()))) + 2
1071    lo = np.maximum(np.minimum(base.min(0), fork) - pad, 0)
1072    hi = np.minimum(np.maximum(base.max(0), fork) + pad + 1, shape)
1073    box = tuple(int(v) for v in hi - lo)
1074    discs = np.zeros(box, bool)
1075    for (y, x), rad in [(fork, fork_radius), *zip(base, radii)]:
1076        rr, cc = draw_disk((y - lo[0], x - lo[1]), rad, shape=box)
1077        discs[rr, cc] = True
1078    n = outward_normal(leader, other, max(length, 10.0))
1079    yy, xx = np.indices(box)
1080    outer = (yy + lo[0] - fork[0]) * n[0] + (xx + lo[1] - fork[1]) * n[1] >= 0
1081    out[lo[0]:hi[0], lo[1]:hi[1]] = convex_hull_image(discs) & outer
1082    return out

1087
1088    Args:
1089        gt: Result of :func:`guided_gt` (its paths and ``radii`` are used).
1090        shoulder_length: Reach of the fill, in multiples of the trunk's

1103def end_direction(path: np.ndarray, length: float) -> np.ndarray:
1104    """Unit vector pointing out of a path at its last point.
1105
1106    The direction is the chord to the last point from the point about
1107    ``length`` px before it (the first point, if the path is shorter), which
1108    ignores pixel-scale wiggles.
1109
1110    Args:
1111        path: ``(N, 2)`` path points, in order.
1112        length: Chord length (px).
1113
1114    Returns:
1115        ``(2,)`` unit vector ``(d_row, d_col)``, or zeros if the path has no length.
1116    """
1117    if len(path) < 2:
1118        return np.zeros(2)
1119    back = arc_length(path)
1120    back = back[-1] - back                              # distance back from the last point
1121    d = (path[-1] - path[int(np.argmin(np.abs(back - length)))]).astype(float)
1122    size = np.hypot(*d)
1123    return d / size if size > 0 else np.zeros(2)

1126def end_cut(path: np.ndarray, radius: float) -> tuple[np.ndarray, np.ndarray] | None:
1127    """A flat end for a path drawn as discs: the line through its last point, square to it.
1128
1129    Drawn as a union of discs, a path ends in a half disc of its radius
1130    there. Pixels beyond this line (see
1131    :attr:`treeskel.winter_gt.WinterGT.trunk_cuts`) are not drawn, which
1132    squares the end off. The direction is taken over the path's last
1133    ``radius`` px (:func:`end_direction`).
1134
1135    Args:
1136        path: ``(N, 2)`` path points, ending at the end to cut.
1137        radius: The drawing radius at that end (px).
1138
1139    Returns:
1140        ``(point, outward direction)`` as float arrays, or None if the path
1141        has no direction there.
1142    """
1143    d = end_direction(path, float(radius))
1144    return (path[-1].astype(float), d) if d.any() else None

1147def fork_junction(gt: WinterGT, reach: float) -> np.ndarray:
1148    """Pixels joining the trunk's flat top to each leader's outer edge with a straight side.
1149
1150    With the trunk cut flat at the fork (:func:`end_cut`), each leader
1151    is joined to the trunk on its outer side (:func:`outward_normal`): the
1152    join is the convex hull of the trunk's top from the fork to its edge on
1153    that side, and of the leader's discs up to ``reach`` trunk radii along
1154    it, kept to the outer side of the leader's direction. Its outer edge is
1155    then the straight line from the trunk's edge to the leader's edge, and
1156    the crotch between the leaders is left as the leaders' own discs draw
1157    it: a V, not the round top of the trunk. The shoulder fill
1158    (:func:`shoulder_fill`) is similar but takes the trunk's round end disc
1159    into the hull, so the round top stays.
1160
1161    Args:
1162        gt: A guided result with fitted ``radii``; its trunk ends, and both
1163            leaders start, at the fork.
1164        reach: How far up each leader the join reaches, in trunk radii at
1165            the fork (:attr:`GuidedParams.junction_reach`); 0 or less gives
1166            an empty mask.
1167
1168    Returns:
1169        ``(H, W)`` bool mask of the join, to be added to the drawn branches.
1170    """
1171    shape = gt.tree_mask.shape
1172    out = np.zeros(shape, bool)
1173    if reach <= 0 or len(gt.trunk) < 2 or len(gt.left) == 0 or len(gt.right) == 0:
1174        return out
1175    radius = _fork_radius(gt.radii)
1176    up = end_direction(gt.trunk, radius)
1177    if not up.any():
1178        return out
1179    fork = gt.trunk[-1]
1180    across = np.array([-up[1], up[0]])                   # square to the trunk, along its flat top
1181    for side, other in (("left", gt.right), ("right", gt.left)):
1182        leader, radii = getattr(gt, side), gt.radii[side]
1183        outer = outward_normal(leader, other, max(reach * radius, 10.0))
1184        if not outer.any():
1185            continue
1186        corner = fork + radius * (across if across @ outer >= 0 else -across)   # the trunk's edge on this side
1187        base = arc_length(leader) <= reach * radius       # a prefix: arc length only grows
1188        # Work in a box around the fork that holds the top and every disc (and so their hull).
1189        pad = int(np.ceil(radii[base].max())) + 2
1190        points = np.vstack([fork, corner, leader[base]])
1191        lo = np.maximum(np.floor(points.min(0)).astype(int) - pad, 0)
1192        hi = np.minimum(np.ceil(points.max(0)).astype(int) + pad + 1, shape)
1193        if np.any(hi <= lo):
1194            continue
1195        box = tuple(int(v) for v in hi - lo)
1196        parts = np.zeros(box, bool)
1197        for (y, x), rad in zip(leader[base], radii[base]):
1198            rr, cc = draw_disk((y - lo[0], x - lo[1]), rad, shape=box)
1199            parts[rr, cc] = True
1200        end = np.round(corner).astype(int)
1201        rr, cc = draw_line(int(fork[0] - lo[0]), int(fork[1] - lo[1]), int(end[0] - lo[0]), int(end[1] - lo[1]))
1202        inside = (rr >= 0) & (rr < box[0]) & (cc >= 0) & (cc < box[1])
1203        parts[rr[inside], cc[inside]] = True
1204        yy, xx = np.indices(box)
1205        keep = (yy + lo[0] - fork[0]) * outer[0] + (xx + lo[1] - fork[1]) * outer[1] >= 0
1206        out[lo[0]:hi[0], lo[1]:hi[1]] |= convex_hull_image(parts) & keep
1207    return out

1215def insert_waypoint(clicks: Clicks, gt: WinterGT, point: Point) -> Clicks:
1216    """Add a correcting click to the part of the trace it is nearest to.
1217
1218    The point joins the trunk, left or right control points, whichever traced
1219    path passes closest to it, at the position matching its place along that
1220    path. The trunk's root and fork, and the leaders' tips, stay fixed.
1221
1222    Args:
1223        clicks: Current complete clicks.
1224        gt: The current trace (from :func:`guided_gt`).
1225        point: The new ``(row, col)`` click.
1226
1227    Returns:
1228        New :class:`Clicks` with the waypoint inserted.
1229    """
1230    p = np.asarray(point)
1231    best = None
1232    for name in ("trunk", "left", "right"):
1233        path = getattr(gt, name)
1234        if len(path):
1235            d = np.hypot(*(path - p).T)
1236            i = int(np.argmin(d))
1237            if best is None or d[i] < best[0]:
1238                best = (d[i], name, i, path)
1239    _, name, idx, path = best
1240    ctrl = list(getattr(clicks, name))
1241
1242    def pos(q: Point) -> int:
1243        """Index of the path point nearest to ``q``."""
1244        return int(np.argmin(np.hypot(*(path - np.asarray(q)).T)))
1245
1246    # Insert before the first control point that lies further along the path.
1247    # The trunk's first point (root) is fixed, so start after it.
1248    start = 1 if name == "trunk" else 0
1249    k = next((j for j in range(start, len(ctrl)) if pos(ctrl[j]) > idx), len(ctrl))
1250    if name == "trunk":
1251        k = min(max(k, 1), len(ctrl) - 1)   # keep root first and fork last
1252    else:
1253        k = min(k, len(ctrl) - 1)           # keep the tip last
1254    ctrl.insert(k, (int(point[0]), int(point[1])))
1255    new = Clicks(**{**clicks.__dict__})
1256    setattr(new, name, ctrl)
1257    return new

1260def check_clicks(c: Clicks, min_rise: int = 40, min_spread: int = 40) -> list[str]:
1261    """Geometric sanity checks on a tree's clicks (image rows grow downwards).
1262
1263    Flags click-order slips that cannot be right for a Tatura V tree: the fork
1264    not clearly (10 px) above the root, a tip not clearly above the fork, or the two tips
1265    almost on top of each other. It cannot catch an accepted trace that
1266    follows the wrong branch; that needs looking at the overlay.
1267
1268    Args:
1269        c: The tree's clicks.
1270        min_rise: Least height (px) of each tip above the fork.
1271        min_spread: Least sideways distance (px) from the left tip to the right one.
1272
1273    Returns:
1274        Human-readable problems (empty if none, or if skipped/incomplete).
1275    """
1276    if c.skip or not c.complete:
1277        return []
1278    c = c.normalised()
1279    (rr, _), (fr, _) = c.trunk[0], c.fork
1280    issues = []
1281    if rr - fr < 10 and "splits at ground" not in c.note:
1282        issues.append(f"fork only {rr - fr} px above the root (double click, or a tree "
1283                      "that splits at the ground?)")
1284    for side in ("left", "right"):
1285        tip = getattr(c, side)[-1]
1286        if fr - tip[0] < min_rise:
1287            issues.append(f"{side} tip only {fr - tip[0]} px above the fork")
1288    if c.right[-1][1] - c.left[-1][1] < min_spread:
1289        issues.append("leader tips are close together")
1290    return issues

452

454    a residual (the path's sideways wiggle). Only the residual is smoothed,
455    with a Gaussian of width ``sigma`` (in path steps, about pixels), after
456    an odd reflection at each end, which keeps the residual zero there. Real
457    bends are kept, pixel-scale zig-zags are removed, and the result is
458    re-drawn as a connected 8-connected pixel path.
459

461        seg: ``(M, 2)`` connected path from one click to the next.

465        ``(K, 2)`` int connected path with the same first and last points.
466    """

468        return seg

470    step = np.hypot(*np.diff(p, axis=0).T)
471    t = np.concatenate([[0.0], np.cumsum(step)])

632    """Robust straight-line fit ``y ≈ a + b·x`` by Huber regression.
633
634    Iteratively reweighted least squares: residuals within ``k`` robust
635    standard deviations (scale = 1.4826 × median absolute residual) get full
636    weight, larger ones weight ``k·σ/|r|``, so outliers pull the line far less
637    than in ordinary least squares.
638
639    Args:
640        x: Positions.
641        y: Values, one per position.
642        k: Huber's tuning constant (in robust SDs).
643        iters: Most reweighting rounds.
644
645    Returns:
646        ``(a, b)``; ``b = 0`` if ``x`` has no spread.
647    """
648    x, y = np.asarray(x, float), np.asarray(y, float)
649    if np.ptp(x) == 0:
650        return float(np.median(y)), 0.0
651    X = np.stack([np.ones_like(x), x], 1)
652    w = np.ones_like(y)
653    beta = np.zeros(2)
654    for _ in range(iters):
655        sw = np.sqrt(w)
656        new, *_ = np.linalg.lstsq(X * sw[:, None], y * sw, rcond=None)
657        res = y - X @ new
658        scale = 1.4826 * np.median(np.abs(res)) or 1e-9
659        u = np.abs(res) / (k * scale)
660        w = np.where(u <= 1, 1.0, 1.0 / np.maximum(u, 1e-12))
661        if np.allclose(new, beta, atol=1e-6):
662            break
663        beta = new
664    return float(new[0]), float(new[1])

805def profile_edges(profiles: np.ndarray, min_background: int = 3, min_half: int = 1) -> tuple[np.ndarray, np.ndarray]:
806    """Where the branch starts and ends in each cross-section profile.
807
808    Each profile is modelled in three pieces and fitted by least squares:
809    the background on one side (a constant colour), the branch (a quadratic
810    in position, per colour channel) and the background on the other side
811    (a constant). A branch lit from one side is bright on that side and dark
812    on the other; the quadratic follows that shading across the whole branch,
813    whereas an edge or ridge detector stops at the change from the lit to
814    the shaded half. Every pair of change points is tried: the squared
815    error of each piece comes from cumulative sums of the samples and their
816    powers, so all pairs are scored at once. The branch must include the
817    centre (the path).
818
819    On synthetic branches lit from the front or either side, of half-width
820    3–9 px with the path up to 2 px off-centre, the half-width was found to
821    within 0.5 px in 47 of 48 cases, and within 1 px in the last (a
822    front-lit branch whose dark rim was as bright as the background).
823    Where a shaded half is as dark as the background next to it, it can be
824    left out; the robust fit along the leader (:func:`fit_leader_radius`)
825    absorbs such points.
826

829            odd, centred on the path (e.g. from :func:`straighten`).
830        min_background: Fewest background samples on each side.
831        min_half: The branch reaches at least this many samples either side
832            of the centre.
833

836        first and last branch samples. The half-width is
837        ``(last − first + 1) / 2``.
838
839    Raises:
840        ValueError: If the profiles are too short for ``min_background`` background and ``min_half`` branch
841            samples on each side.
842    """

844    if p.ndim == 2:
845        p = p[..., None]
846    m, n, _ = p.shape
847    half = n // 2
848    if m == 0:
849        return np.zeros(0, int), np.zeros(0, int)
850    x = (np.arange(n) - half) / max(half, 1)                       # in [-1, 1], for conditioning
851    firsts = np.arange(min_background, half - min_half + 1)
852    lasts = np.arange(half + min_half, n - min_background)
853    if len(firsts) == 0 or len(lasts) == 0:
854        raise ValueError(f"profiles of {n} samples are too short for {min_background} background "
855                         f"and {min_half} branch samples on each side")
856    a, b = (g.ravel() for g in np.meshgrid(firsts, lasts, indexing="ij"))
857    sx = _cumsum0(np.stack([x ** k for k in range(5)]), 1)          # (5, n+1): sums of x^k
858    sxy = _cumsum0(np.stack([x ** k for k in range(3)])[:, None, :, None] * p[None], 2)  # (3, m, n+1, C)
859    syy = _cumsum0((p ** 2).sum(-1), 1)                            # (m, n+1)
860
861    def constant_sse(i0: np.ndarray, i1: np.ndarray) -> np.ndarray:
862        """Squared error of the best constant over samples i0..i1-1, per profile and pair."""
863        s = sxy[0][:, i1] - sxy[0][:, i0]
864        return syy[:, i1] - syy[:, i0] - (s ** 2).sum(-1) / (i1 - i0)
865
866    # Quadratic over a..b: normal equations G β = r, error = Σy² − rᵀG⁻¹r.
867    i0, i1 = a, b + 1
868    gram = np.stack([np.stack([sx[j + k][i1] - sx[j + k][i0] for k in range(3)], -1) for j in range(3)], -2)
869    r = np.stack([sxy[j][:, i1] - sxy[j][:, i0] for j in range(3)], 2)   # (m, pairs, 3, C)
870    solved = np.einsum("pjk,mpkc->mpjc", np.linalg.inv(gram), r)
871    quadratic = syy[:, i1] - syy[:, i0] - (r * solved).sum((2, 3))
872    cost = constant_sse(np.zeros_like(a), a) + quadratic + constant_sse(b + 1, np.full_like(b, n))
873    best = np.argmin(cost, 1)
874    return a[best] - half, b[best] - half
