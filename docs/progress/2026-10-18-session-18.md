## 3. `benchmark --flops` (PR #68)

**What it measures**, for each of the five networks, at batch 1 with random weights:
- **FLOPs:** PyTorch's FLOP counter, 2 per multiply-add. The element-wise layers it skips are about 0.5% of the
  work (measured).
- **Memory traffic:** every dispatched operation reads its inputs (weights included) and writes its outputs,
  with views left out. No fusion and no caching (the L2 cache is 2.75 MB, the largest activation 8.4 MB), so
  the traffic is an upper bound and the intensity a lower bound.
- **The roofline** of the GTX 1080 Ti: 11.34 TFLOP/s and 484 GB/s (NVIDIA's specifications), a ridge point of
  23.4 FLOP/byte.
- **Speed:** the FLOP/s implied by `report.json`'s times and by this run's own.
- **`torch.profiler`** over one prediction: the operators; on a GPU, the kernels and their summed time.

**It reproduces the report exactly:**

| Report | Measured |
|---|---|
| 10.8 GFLOP per pass, 21.6 per photo | 10.78 / 21.56 |
| 313 MB, about 34 FLOP/byte | 313.1 MB, 34.4 |
| 4.7 times the work at 480x640 | 4.69 |
| 20% of the GPU's peak | 19.6% |
| 1.9 ms and 1.3 ms at the peak rates | 1.90 / 1.30 |
| CPU about 190 and 220 GFLOP/s | 186 / 218 |

Every network is above the ridge point (34–47 FLOP/byte), so memory bandwidth limits none of them.

**AI errors, and how they were caught:**
- **An explanation in the report was never measured.** It said the GPU "loses time to fixed overheads such as
  launching more than 200 small steps per photo". The 200 was an operator count, not kernels, and the profile
  showed the overheads are about half the story. Caught by measuring with the profiler. The session notes do
  not record where the report's FLOP paragraph was first worked out, so this is listed as found, not
  attributed.
- **Timings taken with the machine busy.** The first run here timed the U-Net on the CPU at 3.3 s instead of
  about 0.1 s, because the test suite was running at the same time. Noticed from the angle CNN taking 30 times
  longer than the identical feature network. Rerun on an idle CPU before anything was committed.
- **Doctests that needed PyTorch.** Two docstring examples would have failed, not been skipped, on a machine
  without PyTorch. Caught before committing; the known answers moved to tests that skip cleanly.
- **A placeholder in a README draft** ("the U-Net's 256x256x... activations alone is 16 MB"). Caught on
  rereading; the largest activation was measured (8.4 MB) and the sentence corrected.
- **Output text that pointed outside the repository** ("the report's Table 5"). Fixed before committing.
- **A README left stale by the next step.** After the student's run replaced the files, the README still said
  they came from the assistant's environment. Fixed in PR #69.

**Lessons:**
- **A figure in a report needs a saved source, even when it is right.** All six figures checked out, but a
  marker could not have known.
- **Measure an explanation before writing it.** "Fixed overheads" sounded right and was half the story.
- **Time on an idle machine,** and compare like with like: two identical networks should take the same time.
- **Optional dependencies must skip, not fail,** in every kind of test, doctests included.
