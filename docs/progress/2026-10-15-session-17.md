## 2. The 3D model in one step (`treeskel.model3d`, PR #65)

**The finding that made it simple:** every one of the 541 trees already has a committed out-of-sample mask:
- the 5-fold run's for the 449 development trees, each from a network that never saw the tree's row;
- the final test's for the 92 test-row trees.

So `build` can pick the mask by itself, and no network has to run.

**What `build` now does** (the student's three choices: the automatic masks as the default, opening the
browser, and a Windows file):
- **`--mask auto` (the new default):**

  | Photo | Mask |
  |---|---|
  | A development tree | its 5-fold mask |
  | A test-row tree | the final test's mask, so its model matches the reported results |
  | A photo from elsewhere, or row 4 (no saved masks) | the trained network (`train` once) |

- **The tree** is looked up in `data/raw`, else `data/sample` or `data/tuning`. The 9-tree sample is enough
  straight after `pip install -e .`.
- **Any of a tree's files** stands for it, each tree once. A dataset kept in season folders falls back to the
  lookup by id.
- **A photo from elsewhere** finds its depth image beside it by name (`RGB` replaced by `D`, as in the
  dataset), or takes `--depth`. A photo dropped together with its depth is built once.
- **The model opens in the browser** (`--no-open` to skip).
- **`model3d.bat`:** drop photos on it, or double-click it and type a tree id. It runs from the repository's
  folder with the `.venv`'s Python. It has CRLF line endings, kept by `.gitattributes`, since `cmd.exe` can
  misread labels without them.
- **The old forms still work:** `--tree`/`--data`, `--rgb`/`--depth`, `--mask unet/saved/hand`.

**Checks:**
- **Byte for byte:** on the 8 sample trees with saved masks, the automatic choice wrote the same 24 files as
  the explicit `--mask saved` commands, with no network loaded.
- **The reported numbers:** R12N02 reads the final test's 49.6° in the photo; R15N05 reads the 3D run's 51.7°
  in the plane.
- **No PyTorch:** a build succeeds with `torch`, `torchvision` and `kornia` blocked from importing (now a test).
- **Speed:** 8 trees in about 2 s on a CPU.
- **Not run here:** `model3d.bat` itself (no Windows). The student tried it on their PC.

**The student's questions about it:**
- **Does it predict a new tree from a winter photo, a summer depth or a summer photo?** No.
  - A new tree needs its summer photo (the network draws the branches from colour) and its summer depth image
    (for the 3D), plus the trained network.
  - The winter photo is never used.
  - "Any of a tree's files" only says which dataset tree is meant; that tree's summer photo and depth are
    still what is built.
  - A truly new photo must also match the camera (this dataset's depth encoding) and the framing (a centred
    two-leader tree).
- **What "drag a photo onto it" means:** Windows drag-and-drop onto `model3d.bat`'s icon. Nothing is copied
  into `data/raw`, and a dataset tree needs only its id.

**AI errors, and how they were caught:**
- **The tool's wording misled me.** The AI wrote "any of a tree's files will do" and "drag a tree's photo
  onto it" without saying that this only identifies a dataset tree. I took it to mean a new tree could be
  predicted from a winter photo or a depth image alone. My question exposed it, and the AI explained what
  each case needs.
- **A first draft counted every file as a photo from elsewhere.** Its test for leaving out dataset-named files
  could never succeed, which would have mixed up `--depth` and the pairing of photos with their depths. Caught
  on the AI's own review before any test ran; rewritten.
- **A check that tested the wrong thing.** To show that no PyTorch is needed, the AI first blocked PyTorch in
  a way that broke scikit-image's own import. That error was not a real failure. Redone with an import hook,
  then kept as a test.
- **Counts by a different method.** The AI's first count gave 460 test functions where session 16 reported
  485, and 534 documented items against 532. It counted `main` the same way and reported the difference.
- **The index's first draft had four errors**, caught by checking it against the READMEs before committing:
  - the shoulder fill's session (6, not 5);
  - the alignment's sessions;
  - which README covers two of the re-run's folders;
  - the leaf study called "not adopted", where its README says it was a description, not a method.
- **Smaller slips, caught before committing:**
  - a test expected an absolute path where the code gives a relative one;
  - the same test used a link, which needs admin rights on Windows;
  - a message repeated itself for row 4;
  - a tree id written after `--data` was read as a folder (found on review; the error now says so).
- **A branch left behind its remote:** after resetting the branch to `main`, it was one merge commit ahead of
  GitHub, which the session's checks flagged. Pushed; no new content.

**Lessons:**
- **Say what each input does, not only that it is accepted.** "Any of a tree's files" was true and still
  misleading.
- **A check must fail only for the reason it tests.**
- **Check a summary against its sources before committing,** even one that only points to other files.
- **Tidy without deleting evidence:** an index makes 57 folders readable without moving a path the code
  depends on.
