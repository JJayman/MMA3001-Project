## 1. Project choice and problem definition

- **Project:** the provided "Apple-tree reconstruction" project (MMA3001 2026
  project brief, Dataset 1: RGB-D Apple-Tree Reconstruction and Orchard Mapping).
- **My idea:** use the *winter* RGB-D image (bare branches) to build a ground
  truth of each tree's **main branches**, then train a model that predicts
  where those branches are from the *summer* RGB-D image, through the leaves.
- **Engineering context:** perception for orchard robots (pruning, harvesting,
  path planning), which must avoid or target branches hidden by foliage.
- **Scope decision:** main branches only (trunk and scaffold limbs), because
  they are stable between seasons, while thin shoots grow or are pruned.

## 2. The data (checked on the committed sample)

- 544 trees in 23 orchard rows; rows contain different numbers of trees.
- Per tree: one summer and one winter viewpoint, each with an RGB and a depth
  image: 4 PNG files, 640x480.
- Filename format: `R01U01_Summer_D-12-40-11.png`, i.e. row, position in row,
  season, `RGB` or `D`, and capture time `H-M-S` (not zero-padded).
- **Depth is 8-bit greyscale** (three identical channels, max value about
  150–180), so it is a scaled visualisation, **not metric depth**.
  - Brighter = closer. 0 = no reading.
  - About 55–60% of winter pixels and 3–30% of summer pixels have no reading.
    In winter, the distance cut-off removes the rows behind, so depth nearly
    isolates the front tree.
- **RGB–depth alignment within a season:** close on R01U01; about 5–15 px
  offset on R02U09. For now, flag it rather than correct it.
- No camera intrinsics, depth scale or sensor model are provided. 640x480
  suggests a Kinect-v1 / Xtion-class sensor.

## 3. Planned method

1. **RGB–depth check/registration** per season (fixed transform fitted by least
   squares to hand-clicked points if an offset is confirmed; report the
   remaining error in px).
2. **Winter ground truth:** combine colour (pale bark against grass) and depth
   (remove invalid/background pixels) into a wood mask. Then skeletonise, build
   a graph, and prune to main branches by length and thickness.
3. **Winter→summer alignment per tree:** 2D affine/homography. Try a learned
   matcher (LoFTR/LightGlue), since SIFT is expected to fail across seasons.
   Anchor on static structure (trunk base, posts, irrigation line). Measure
   error on about 30 trees with hand-clicked points. Flag and exclude trees
   where alignment fails.
4. **Model:** U-Net with a pretrained encoder. Input: summer RGB + depth +
   valid mask. Output: main-branch mask → skeleton.
5. **Estimated 3D:** back-project with assumed intrinsics (f ≈ 525–580 px,
   centre ≈ (320, 240)). Fit the 8-bit → distance mapping so the ground
   comes out planar, and check scale against known orchard dimensions
   (posts, wires, bin). Output: a 3D skeleton at an estimated scale.
6. **Baselines** (the brief requires a comparison):
   - (a) colour + depth threshold on the summer image;
   - (b) a per-pixel random forest;
   - (c) the U-Net.
   Compare on accuracy, runtime and memory.
7. **Metrics:**
   - skeleton precision/recall within a pixel tolerance, with **recall split
     into visible vs leaf-hidden branch** (the headline result);
   - measures that don't need perfect alignment: branch count, junction
     count, trunk angle;
   - a sensitivity analysis of the 3D output to the assumed intrinsics and
     depth mapping.
8. **Ground-truth check:** hand-annotate about 20–30 test-set trees to
   validate the automatic winter ground truth itself.

## 4. Validation design (decided)

- **Split by row, never by image or by tree.** Neighbouring trees share
  background, lighting and capture session, and can appear in each other's
  frames, so a random split would leak information.
- **Hold out whole rows (about 15% of trees) as the final test set.** It is not
  used until the final evaluation, so it cannot influence model selection.
- **5-fold `GroupKFold` by row** on the remaining rows for model/hyperparameter
  selection. A GPU is available, so full k-fold training is feasible.
