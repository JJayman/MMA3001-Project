## 2. The related paper (Chen et al., 2020)

Chen, Z., Ting, D., Newbury, R., Chen, C. (2020). *Semantic Segmentation for
Partially Occluded Apple Trees Based on Deep Learning.* arXiv:2010.06879.

- **Same orchard and camera, different capture.** They used 521 autumn images
  (end of May, 4–5:30 pm, no apples). Ours are summer (apples visible, about
  11 am–2 pm) and winter captures.
- **What carries over:**
  - Intel RealSense D435, 640x480, depth aligned to RGB by the camera. So the
    RGB–depth registration step is no longer needed; the small 5–15 px
    offsets seen are normal D435 edge error.
  - 2D open-V (Tatura trellis): each tree is a trunk plus two leaders in a V.
    This defines "main branches" precisely, and the V angle is a useful
    measure.
  - Rows 4.125 m apart, trees 0.6 m apart (about 180 px at 2 m), camera to
    canopy 1.8–2.2 m. These are scale checks for the 3D estimate.
  - They analysed depth below a 4 m maximum.
- **Their result:** U-Net (ResNet34 encoder, RGB-D input, weighted Dice loss)
  reached **78.5% occluded-branch recall**, the best of the models they tried.
  This is the benchmark to compare against.
- **Where this project differs, and why it matters:** their occluded-branch
  labels were hand-drawn guesses. Ours come from the same tree photographed
  bare in winter, which records where the branches actually are. This is the
  main argument for the project.
- **Ideas taken from the paper:**
  - Its metrics (IoU, boundary F1, branch recall, occluded-branch recall), so
    results are directly comparable.
  - Weighted Dice loss, because branch pixels are only about 6% of the image.
  - Its suggested future work: fitting curves (least squares) to the
    predictable V shape, as a numerical-method baseline or post-processing
    step.

## 3. Depth encoding (hypothesis, not yet tested)

On the sample, value ≈ 255·(1 − d / 4 m) puts the leafy canopy (values about
140–150) at roughly 1.7–1.8 m, close to the documented 1.8–2.2 m. Ground at the
bottom of the image reads *farther* than the canopy, which fits a camera
roughly 1 m above the ground looking horizontally. This will be tested
properly in the depth-calibration step (ground-plane fit plus the known
spacings).

## 4. Data problems found and fixed

| Finding | Action |
|---|---|
| Row 4 winter files use a different name, e.g. `R04U01_Winter_RGB-R04N03_RGB_12-17-14.png` | Loader accepts the variant and keeps `R04N03` as `source_id` |
| Row 4 winter **depth** files embed `_RGB_` (`R04U01_Winter_D-R04N03_RGB_…`) | The outer `RGB`/`D` label decides the modality; the embedded label is recorded. `--check-images` confirms each depth file really is greyscale |
| Row 4 N numbers skip (U01→N03, U03→N07, U10→N16…): likely discarded frames, then renumbered | Reported by the CLI; only relevant if row 4 were used |
| **All 31 row 4 winter depth images are the same image** (spotted by eye) | **Row 4 excluded** in `treeskel.io.EXCLUDED_ROWS`, with the reason. Raw data untouched; `--include-all-rows` overrides |
| No automatic check for repeated images | `find_identical_images` added; `--check-images` lists identical-image groups |

**Final dataset: 513 trees in 22 rows** (544 minus the 31 in row 4).

## 8. Late finding: are summer and winter "U" numbers the same tree?

On the unit forum, staff answered another student: *"There is an image in the
folder [that] shows the Rows ('R') and Number ('N'). U is for unmatched
trees."* Every file except row 4 winter uses U numbers.

- **Interpretation:** U numbers are most likely the order in which trees were
  photographed within a row in each capture. They were **not checked against
  the orchard map** (the N numbers). That does not make the trees unusable, but
  `R01U01_Summer` and `R01U01_Winter` are only the same physical tree if both
  captures photographed the same trees, in the same direction, with no skips.
  This is an **assumption to test**, not a given.
- **Evidence so far (8 sample trees, by eye):**
  - R06U12: a green tree guard on the right of the trunk in both seasons.
    Strong evidence of a match.
  - R02U09: a post just right of the tree in both seasons.
  - R01U01 and R01U02: the same distinctive trunk bends in both seasons.
  - R06U13 and R17U09/U10: plausible, but not conclusive.
  - Every row except row 4 has the same number of trees in both seasons,
    which fits consistent numbering. It is not proof.
- **Also noted:** the summer photos are framed much closer than the winter
  ones, so winter→summer alignment must handle a large change in scale.
- **Plan:**
  - Find the map image in the dataset folder.
  - Verify pairing on a spread of trees from every row, using written
    criteria (trunk shape, V angle, posts, tree guards, wires), and report the
    match rate.
  - If mismatches appear, a within-row sequence alignment (dynamic
    programming over trunk features) could re-pair trees. That directly
    addresses the "matching trees across seasons" direction in the dataset
    brief.
- **Orchard map (from the dataset folder):** R counts rows west to east, and
  N counts trees north to south within a row. Risk: if the two seasons walked
  a row in opposite directions, U numbers would pair the wrong trees. Check
  pairs at both ends and the middle of long rows (20–23). Also, the photographed
  counts per row do not follow the row lengths on the map (rows 19–23 have the
  most trees), so the photos may cover only part of each row. Asked staff.
- **Masks:** the dataset includes 256×256 main-branch masks (trunk + two V
  leaders), named like the summer images, e.g. `…_Summer_…`. They match the
  summer photos by eye. Chen et al. describe hand-labelled masks after a
  480×480 centre crop (x = 80–560) and resize to 256×256. Their Branch class
  includes occluded sections, but the paper covers only its autumn images.
  - **Decision: masks are used for validation only, not training.** The
    winter-derived labels remain the project's contribution.
  - Each summer tree then has two independent references: the winter-derived
    labels (what is actually there) and the hand mask (a human guess through
    the leaves). Their agreement tests the ground-truth pipeline and the
    alignment. Where they disagree on hidden branches, the winter photo
    shows which is right.
  - Masks from the test rows (12, 18, 21) stay unused until the final
    evaluation. Any tuning of the ground-truth pipeline uses development-row
    masks only.
