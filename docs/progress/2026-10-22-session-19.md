## 5. The docstrings

**How:**
- A script listed, for each public function, the sections it lacked, with its signature, docstring, return
  and raise statements.
- For each of the 27 modules, a specification of the new sections was written after reading the code.
- The script inserted the sections in Google order (Args, Returns, Raises, before any Example). It refused
  any `Args` whose names differed from the signature.
- Classes already documented their constructors (`Args`) or fields (`Attributes`), so `__init__` methods
  were left to them, as Google style allows.

**Result:**
- **385 functions gained sections:** 340 `Args`, 278 `Returns`, 9 `Raises`.
- **29 existing `Args` sections fixed:** they grouped parameters (`rgb, depth, valid: ...`) or missed some
  (e.g. `benchmark.mask_post_processing`'s `n` and `repeats`).
- `Overlay`'s grouped attributes were split.
- Of the 526 public functions and methods, every one that takes arguments lists them (485, the rest take
  none or are documented by their class). 456 have `Returns`, 28 `Raises`.
- **No code changed:** `git diff` touches only docstrings. The doctests pass, and pdoc renders the sections
  as argument lists.

**`tests/test_docstrings.py`** (new, 8 test functions, 35 tests). It reads the source, imports nothing, so it
needs no optional dependency. It fails if:
- a public function's `Args` differ from its signature (names and order);
- a function that returns or raises does not say so;
- a dataclass's `Attributes` differ from its fields;
- a class's `Args` differ from its `__init__`.

Its checker is tested on small sources with known answers: complete, missing, renamed and grouped
arguments, missing sections, exempt helpers, dataclasses.

**AI errors, and how they were caught:**
- **The first insertion of sections put the blank lines in the wrong places** (two blank lines, none before
  `Args`). Caught by reading the diff before committing; reverted and the script fixed.
- **A correction lost to the shell.** An unquoted heredoc swallowed the backticks, so a fix to two
  `depth3d` docstrings did not apply. They went in saying `ground_blocks` returns an empty array when no
  block qualifies, and `affine_error` gives `inf` below 3 blocks. Caught by the patch's assertion; corrected
  from the code (with fewer than 12 blocks all are returned unfiltered; `inf` below 4).
- **First drafts that contradicted the code**, corrected after reading it, before committing:
  - `huber_location` returns its last estimate, not the median, if it does not settle;
  - `draw_joins` always returns a sheet;
  - `summarise_run`'s key is `n`, not `trees`;
  - `bend3d`'s sources are `"hand masks"`/`"U-Net"`, not `"hand"`/`"unet"`;
  - `free_taper`'s NaN conditions;
  - `splits.main` raises on a split that does not fit, rather than printing.
- **The script missed two grouped `Args` sections** (`segment.compare_with`, `measure_registration.split_half`).
  It treated a section whose every entry was grouped as having no names to compare. The new test, written
  to be stricter, caught both. The docstring commit's message says 28 such sections; it was 29 (27 + 2).
- **README claims checked before committing:**
  - "distance from the camera" became "depth along the camera's axis";
  - a sentence that the images show no people was removed (not checked on every image);
  - the reproduction steps were reordered, because `score_baseline` reads the U-Net's predictions;
  - the claim that steps 2 and 3 need only the repository was tested on a fresh clone.
- **The review's counts were rough:** it said "about 22" incomplete `Args` sections; the full count was 29.

**Lessons:**
- **A checker should be stricter than the tool it checks.** The test found what the script let through.
- **Read the code, not the docstring's prose, before describing a return value.** Six first drafts were
  wrong in ways the prose did not show.
- **Quote heredocs that carry code.** A shell can silently change it.
