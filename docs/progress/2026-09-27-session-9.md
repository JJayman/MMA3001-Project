Correcting the depth–colour registration found at the end of session 8 (the
student's first item). The measurement became a package module and ran on

## 1. The measurement in the package (`treeskel.measure_registration`)

- **The method (session 8's):** across each traced leader, the depth run's
  centre minus the bark's centre found in colour, fitted as a fixed image
  shift (Huber). Pooled, per orchard row, per tree, in bands of the image,
  and with an affine term. The depth is also moved by 36 trial moves with the
  paths kept.
- **Development rows only**, loaded as stored (`register=False`), or with the
  correction (`--registered`) to check it.
- **Reproduces session 8 exactly** on the 21 local trees: 9,988
  cross-sections, dy +3.19 px, dx −0.63 px, and the same table of moves.
- **`treeskel.io`:** `shift_image`, `DEPTH_SHIFT` and
  `load_tree(register=True)`, so every consumer (tracing, rendering, the click
  tool, the checks, the automatic baseline) gets the same corrected depth.

## 2. Why session 8's estimate was low

- **Selection explains part.** A move of the depth changes the fit by only
  0.87–0.90 px per row, because which cross-sections are usable changes with the
  move. On the cross-sections usable both before and after, each difference
  changes by exactly the move (slope 0.985).
- **The colour centre follows its window.** Moving each cross-section's
  window along its normal, with the images unchanged:

  | Window moved (px) | −2 | −1 | +1 | +2 |
  |---|---|---|---|---|
  | Colour centre moved, mean (px) | −1.47 | −0.67 | +0.56 | +0.99 |
  | Colour centre moved, median (px) | 0.00 | 0.00 | 0.00 | 0.00 |
  | Depth centre moved (px) | 0.00 | 0.00 | 0.00 | 0.00 |

  Most cross-sections do not move; some jump as clutter enters or leaves the
  window's ends. On synthetic bark the pull is 0.04–0.22 (sharp or blurred
  edges, grass or a dark background), so it comes from real clutter.
- **So the estimate depended on the paths.** The windows sit on the traced
  paths, which follow the misplaced depth. Traced again with the depth moved
  up 4 rows, the same images read +0.68 px instead of −0.20.
- **Tried, and did not remove it:** traced again with the depth up 4 rows,
  Tukey's biweight still read +0.70 px, least absolute deviations +0.70, and
  only the cross-sections stable under ±2 px window moves +1.01 (all about
  −0.2 on the kept paths); re-centring each window on its own estimate cut
  the pull only from 0.64 to 0.37 in six rounds while the estimates wandered.
- **Three estimates the pull affects less** were added: cross-sections with
  both edges clear; the colour measured in a window centred on the depth run
  (zero exactly where the depth lines up, whatever the pull, but it magnifies
  any bias of the colour fit itself); and each tree traced again with the
  depth moved up 4 and 5 rows.

## 3. A check for summer: mutual information, not good enough

- **Rejected first:** a check along single depth edges (the colour step along
  each depth edge's normal). Exact on a synthetic scene; on winter it read
  0.9 px where the leaders read 3.2, and moved 0.2–1 px for known moves of
  3–4 px. Across thin, shaded bark there is no single step to find.
- **The summer depth is heavily smoothed:** apples do not show in it, and
  posts in front of foliage give weak depth edges.
- **Mutual information** (the usual measure for registering images from
  different sensors) needs no traced branches.
  - Its highest point wanders on a plateau: depth reaches about 2 px past what
    it sees, so every shift within 2 px scores within 0.2%. On synthetic scenes
    the highest point missed by up to 1.54 px; the vertex of a fitted
    quadratic misses by at most 0.15 px, and is used.
  - **In winter it is unreliable:** by bands of rows it reads 1.9, 2.4 and
    4.0 px where the leaders read 2.6, 3.1 and 3.0; single trees barely agree
    with the leaders (r = +0.23 on 449); and 184 of 449 trees and 7 of the 16
    rows (all captured after 12:55) peak at the edge of the search.
  - **Summer: 2.28 px down** (95% CI 2.13–2.41), 0.67 left. Not used.
- **Other references tried:** the student's correction clicks (few on a
  closed depth run; placed where depth misled the trace), crops of the depth
  outline (bark edges too ambiguous to judge to 1 px), and the drip-line hose
  (the depth rarely sees it).

## 9. AI use in this session (for the reflection)

- **What was mine:**
  - choosing to run all 449 trees before deciding, which gave the row-by-row
    evidence the choice rests on;
  - choosing 5 rows up from the three options;
  - running the registration measurement, the re-render and both re-checks on
    my PC;
  - judging the corrected masks by eye ("not sure they look that much
    better"), which matched the size of the change;
  - keeping the correction, and wrapping up.
- **AI errors, and how they were caught:**
  - **Session 8's estimate was low.** The AI's session-8 method measured the
    bark in a window on the traced path, and the result followed the path.
    Found this session when paths traced with a moved depth gave a different
    answer on the same images.
  - **A summer check that did not work.** The single-edge check was built and
    run on real images before being tested on a known shift; on winter it
    barely followed known moves, and was rejected.
  - **Mutual information's peak.** Read as the highest point, it missed known
    shifts by up to 1.5 px; a synthetic known-answer test failed, which led to
    the fitted quadratic. A row's peak later extrapolated to 113 px and made
    the first per-row chart unreadable; peaks are now kept within the search.
  - **A border artefact.** Moving the depth leaves rows of "no reading", which
    made mutual information peak at the edge; found by the plumbing test and
    fixed with a margin.
  - **Claims from 21 trees, again.** The AI recommended the clear-edge subset
    as the best-behaved estimate from 21 trees; on 449 it was biased. The
    21-tree fork and width previews also failed on 449.
  - **Fixes that did not work:** robust fits, a stability filter and
    re-centring did not remove the pull; the existing clicks were tried twice
    as a reference and were too few and biased.
  - **A contradictory sentence** in the results README ("selection is not the
    cause ... because the set changes"), corrected at wrap-up.
  - **Smaller slips:** a script guard that made an import exit silently; a
    test tolerance too tight for sampling noise; a synthetic surface whose
    cross term moved its vertex; an assertion too strict at extreme moves.
    All caught by running the tests before committing.
- **Lessons:**
  - A measurement taken in a window placed by another measurement can inherit
    that measurement's error: here the colour fit followed the paths, and the
    paths followed the depth.
  - Test every new check on a known shift before trusting it on real images.
  - 21-tree results failed on 449 again, including the AI's own
    recommendation. The full set decides.
  - Some corrections are right without being visible: a 0.9 px move cannot be
    judged by eye; the checks against depth show it.
